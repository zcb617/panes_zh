# 第二阶段：项目管理设计

## 一、阶段目标

改造主界面侧栏的“添加项目”业务，让用户先选择本地项目或远端项目。选择远端后，用户从已配置的 SSH 连接中选择一台电脑，浏览该电脑上的目录并添加项目。

项目一经创建，就通过稳定的 `ssh_connection_id` 与远端电脑绑定；后续文件、Git、终端、对话都从项目绑定关系解析执行目标，前端不能临时改发到另一台机器。智能体运行工具和定时任务所属总计划阶段当前均已暂缓，不作为当前执行项。

## 二、业务范围

本阶段包含：

- 主界面“添加项目”的本地/远端类型选择。
- 保留现有本地目录选择流程。
- 远端主机下拉选择。
- 查询选中远端电脑的 HOME 和目录列表。
- 路径输入、目录进入、返回上级和刷新。
- 远端项目名称生成和用户修改。
- 远端项目创建、去重、显示、归档和恢复。
- SSH 连接软删除后隐藏关联项目，连接恢复后原项目重新出现。
- 项目数据结构从“只有本地路径”升级为“本地或 SSH 执行目标”。

本阶段不包含：

- 远端文件编辑、Git 和终端的完整工作区功能，它们在第三阶段实现。
- 远端对话和模型能力，它们在第四阶段实现。
- 从项目创建弹窗中新建或编辑 SSH 连接；连接仍在设置页统一管理。

## 三、概要设计

### 3.1 现有入口改造

当前侧栏“项目”标题右侧的加号直接打开本机目录选择器。改造后：

1. 点击加号打开“创建项目”类型选择弹窗。
2. 弹窗显示“本地”和“远端”两张选择卡。
3. 默认选中“本地”。
4. 用户点击“下一步”进入对应流程。

计划改造入口：

- `src/components/sidebar/Sidebar.tsx`：把 `onOpenFolder` 调整为打开创建项目流程。
- 新增项目类型弹窗和远端项目弹窗。
- `src/stores/workspaceStore.ts`：增加远端项目创建和目标状态。
- `src/lib/ipc.ts`、`src/types.ts`：增加远端目录和远端项目接口。

### 3.2 本地项目流程

选择“本地”后关闭类型弹窗，继续调用现有系统目录选择器和 `open_workspace` 流程。现有本地路径归一化、仓库扫描、项目归档和恢复行为保持不变。

### 3.3 远端项目流程

选择“远端”后打开“新建远程项目”弹窗，包含：

- 项目名称输入框。
- 远端主机下拉框。
- 当前路径输入框。
- 返回上级、回到 HOME、刷新按钮。
- 当前目录下的文件夹列表。
- “取消”和“添加项目”按钮。

远端主机下拉只展示数据库中 `connection_status = 'ok'`、启用且未删除的 SSH 连接。连接检测失败、连接中、禁用或已删除的连接不显示，也不能用于创建远端项目。

## 四、详细交互设计

### 4.1 类型选择弹窗

弹窗标题为“创建项目”。

“本地”卡片说明：在当前电脑上编辑、运行和测试文件。

“远端”卡片说明：选择已连接电脑上的文件夹。

交互：

- 点击卡片或卡片单选圆点切换类型。
- 双击卡片等价于选择并进入下一步。
- `Esc` 或右上角关闭只关闭弹窗，不改变当前项目。
- 选择远端但没有可用 SSH 连接时，仍允许进入远端弹窗，在主机区域展示“请先到设置 → 连接添加远端电脑”，并提供跳转设置的按钮。

### 4.2 打开远端项目弹窗

1. 查询数据库中的未删除连接，只保留 `connection_status = 'ok'`、启用的连接。
2. 优先选择用户上次使用的远端连接；不存在则选择列表第一项。
3. 通过连接 ID 查询远端 HOME。
4. 路径框填入 HOME 的实际绝对路径。
5. 查询该目录的直接子目录并展示。
6. 项目名称暂时为空，用户选定目录后自动填入目录名。

上次选择只用于弹窗默认值，不参与项目的执行目标判断。

### 4.3 切换远端主机

用户从下拉框选择另一台电脑时：

1. 取消前一台电脑尚未完成的目录请求。
2. 清空目录列表和旧错误。
3. 查询新连接的 HOME。
4. 路径回到新连接 HOME，不能把上一台电脑的路径直接带过去。
5. 使用新请求序号更新界面，旧机器迟到的响应不得覆盖当前列表。

### 4.4 浏览远端目录

目录浏览统一通过系统 SSH 执行，不引入另一套远端文件协议。

用户可以：

- 单击文件夹：选中该目录，路径框和项目名称预览随之更新。
- 双击文件夹：进入该目录并加载其子目录。
- 点击返回上级：在远端通过路径解析得到父目录，不能在前端按字符串随意截断。
- 点击 HOME：回到远端登录用户 HOME。
- 点击刷新：重新查询当前目录。
- 在路径框输入 Linux 绝对路径并回车：后端解析 `realpath` 后加载。

列表只展示目录，不展示普通文件。返回项包含目录名、实际绝对路径、是否可读和是否可进入；隐藏目录按现有产品的文件展示约定处理，不新增单独开关。

目录查询失败时保留当前主机选择，展示具体原因：连接禁用、连接已删除、不可达、目录不存在、无权限或路径不是目录。

### 4.5 项目名称

选择目录后，项目名称默认取实际目录的最后一级名称。用户可以修改显示名称。

项目名称只是 Panes 中的 label：

- 修改名称不重命名远端目录。
- 修改名称不改变 `root_path`。
- 修改名称不改变 `ssh_connection_id`。
- 名称可以与其他项目相同，项目身份由 UUID 决定。

### 4.6 添加项目

“添加项目”按钮可用条件：

  - 已选择一条状态为 `ok`、启用且未删除的连接。
- 目录查询成功。
- 后端确认所选路径为可进入的 Linux 绝对目录。
- 项目名称非空。

点击后：

1. 前端提交连接 ID、用户输入名称和当前候选路径。
2. 后端重新从数据库加载连接，拒绝前端覆盖 Host 等参数。
3. 后端通过该连接执行 `realpath`，得到最终实际绝对路径。
4. 后端检查 `(ssh_connection_id, realpath)` 是否已经存在。
5. 创建不可变项目 UUID 并保存。
6. 返回完整 Workspace DTO。
7. 前端把项目加入侧栏、设为当前项目并展开。

如果项目已经存在：

- 未归档项目：不创建新记录，提示“该远端目录已添加”，并可直接切换到原项目。
- 已归档项目：提示恢复原项目，恢复后复用原项目 ID。
- 因连接已删除而隐藏的项目：不能在普通创建流程中绕过隐藏状态，提示先恢复 SSH 连接。

### 4.7 远端项目在侧栏的表现

远端项目沿用现有项目树结构，并增加轻量远端标识和连接名称提示。项目右键菜单仍支持重命名、固定和归档。

第一版不在侧栏增加第二套机器树，不允许从项目菜单切换绑定连接。需要迁移到另一台远端电脑时，按新项目处理，避免原项目对话和任务被静默改发到另一台机器。

### 4.8 SSH 连接删除与恢复对项目列表的影响

查询普通项目时，远端项目必须同时满足：

```text
workspace.archived_at IS NULL
AND ssh_connection.deleted_at IS NULL
```

删除 SSH 连接后：

- 关联项目不删除、不归档，只从普通项目列表隐藏。
- 项目、仓库、线程、消息和任务 ID 均保持不变。
- 不修改项目自身的 `archived_at`，避免连接恢复时无法区分“用户主动归档”和“因连接删除而隐藏”。

恢复 SSH 连接后：

- 原项目自动重新出现在项目列表。
- 用户主动归档的项目仍留在归档区，不自动恢复。
- 当前项目若已经不存在于可见列表，应用切换到下一可见项目或空状态。

连接禁用与删除不同：禁用不隐藏项目，侧栏保留项目并显示“连接已禁用”；进入项目后所有远端执行入口不可用。

## 五、执行目标设计

Workspace 增加明确位置类型：

```text
ExecutionTarget
├── Local
└── Ssh(connection_id)
```

后端新增 `ExecutionTargetResolver`：

- 输入 `workspace_id`，查询项目记录。
- 本地项目返回 Local 和本地根路径。
- 远端项目连接未删除且启用时返回 Ssh、连接 ID 和远端根路径。
- 连接禁用、删除或不存在时返回稳定业务错误。

任何后续业务都只能提交 `workspace_id`、`thread_id` 或 `scheduled_task_id`，再由后端解析目标。前端不能通过额外参数把远端项目改成本机执行，也不能临时指定另一条连接。

## 六、数据设计

### 6.1 Workspace 字段

`workspaces` 增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `location_kind` | TEXT | `local` 或 `ssh` |
| `ssh_connection_id` | TEXT | 远端项目必填，本地项目为空 |

现有 `root_path` 保留：

- 本地项目保存本机绝对路径。
- 远端项目保存远端 Linux `realpath` 后的绝对路径。

`ssh_connection_id` 外键关联 `ssh_connections.id`，物理删除策略为 `RESTRICT`。首版连接不物理删除。

### 6.2 唯一性

现有 `root_path TEXT NOT NULL UNIQUE` 不能继续使用，因为不同机器可能有相同路径。迁移后约束为：

```text
本地项目：root_path 唯一
远端项目：ssh_connection_id + root_path 唯一
```

远端 Linux 路径按大小写敏感处理，不能使用现有 Windows 路径小写归一化逻辑。

现有单列唯一约束定义在表结构中，迁移必须在事务内重建 `workspaces` 表，恢复全部字段、索引和外键，并在提交前执行外键一致性检查。失败时整体回滚。

数据库迁移保护要求：

- 任何字段或表结构变更前，先对当前 `workspaces.db` 做一致性备份；备份失败时立即终止迁移，不执行后续结构变更。
- 备份文件名必须包含迁移版本、变更原因和时间戳，例如：`workspaces.db.backup-before-005-workspace-location-YYYYMMDD-HHMMSS.mmm.db`。
- 备份不能覆盖历史备份，保留所有备份文件，便于根据原因定位引入异常的版本并恢复数据库。
- 使用 SQLite 一致性备份方式，确保 WAL 模式下的最新数据也包含在备份中。
- SSH 连接状态字段迁移使用独立版本 `006`，已有数据库会先生成带有 `006-ssh-connection-status` 原因的备份。
- `006` 迁移执行前检查字段是否已存在，重复启动或迁移中断恢复时不会重复添加字段。

### 6.3 SSH 连接监听状态

`ssh_connections.connection_status` 的取值为：

| 状态 | 含义 |
| --- | --- |
| `unknown` | 尚未启动监听或配置刚发生变化 |
| `connecting` | 正在建立标准 SSH 会话 |
| `ok` | SSH 会话已建立，允许创建远端项目 |
| `failed` | SSH 会话已断开或建立失败，立即重连 |
| `disabled` | 连接已停用，监听已停止 |
| `deleted` | 连接已软删除，监听已停止 |

连接新增或恢复后立即启动监听，修改连接时先停止旧监听、保存新配置并启动新监听；停用和删除立即停止监听。每个连接 ID 同时最多存在一个监听任务，状态更新带有配置版本校验，旧监听不能覆盖新配置的状态。

监听只使用标准 SSH 会话和 SSH 保活参数，不依赖远端 CLI、HTTP 或自定义接口。连接失败不使用退避，直到建立成功；连接成功后保留 SSH 会话，断开时立即进入重连流程。

### 6.4 DTO

Workspace DTO 增加：

```text
locationKind
sshConnectionId
connectionDisplayName
connectionEnabled
connectionDeleted
```

其中连接状态字段用于界面展示，不作为后端执行判断依据；每次执行仍重新解析数据库中的实际状态。

## 七、后端接口设计

| 命令 | 用途 |
| --- | --- |
| `get_ssh_connection_home` | 获取连接的 HOME 和系统信息 |
| `list_ssh_directories` | 查询指定远端目录的直接子目录 |
| `resolve_ssh_directory` | 校验并解析远端实际绝对目录 |
| `create_ssh_workspace` | 创建远端项目 |
| `open_workspace` | 保留现有本地项目流程 |
| `list_workspaces` | 返回可见本地项目和连接未删除的远端项目 |
| `list_archived_workspaces` | 返回用户主动归档的可恢复项目 |

远端目录参数必须经过：

- POSIX 路径校验。
- 安全参数传递或可靠转义。
- 远端 `realpath`。
- 是否为目录、是否可读和是否可进入检查。

连接 ID 只能用于查询持久化连接，不能接受前端附带的连接参数覆盖。

## 八、阶段过渡状态

第二阶段结束但第三、第四阶段尚未完成时，远端项目可以被创建和显示。进入远端项目后：

- 尚未完成的文件、Git、终端和对话入口显示“远端工作区将在下一阶段启用”。
- 不允许现有本地实现拿远端 Linux 路径在本机运行。
- 不允许为了界面可用而临时降级到本地。

这一限制只存在于分阶段开发过程，第三、第四阶段完成后分别解除。

## 十、测试设计

### 10.1 数据迁移测试

- 旧数据库全部本地项目迁移后自动为 `location_kind = local`。
- 迁移前后的项目、线程、消息、仓库和任务 ID 不变。
- 本地重复路径仍被拒绝。
- 两台远端电脑允许添加相同 `/home/user/project`。
- 同一远端电脑不允许重复添加同一实际目录。
- 远端大小写不同路径按 Linux 规则区分。
- 外键一致性检查通过，迁移失败可完整回滚。
- 旧数据库升级前先生成带版本和原因的备份，备份文件可独立打开并保持迁移前结构。
- 备份失败时数据库结构不发生变化。

### 10.2 业务测试

- 点击加号先出现本地/远端选择。
- 本地流程与当前版本一致。
- 远端下拉能在多条连接间切换，目录立即切换为目标机器内容。
- 手输路径、进入目录、上级、HOME 和刷新可用。
- 不可达、禁用、删除、无权限和不存在目录提示准确。
- 重复添加时正确切换或恢复原项目。
- 修改项目显示名称不改变远端路径。

### 10.3 删除恢复测试

- 删除连接后关联项目从普通列表隐藏，但数据库记录和 ID 保留。
- 恢复连接后原项目自动重新出现。
- 用户主动归档的项目不会因连接恢复而自动取消归档。
- 禁用连接时项目仍显示，但远端入口不可执行。

## 十一、阶段验收标准

1. 主界面添加项目时先选择“本地”或“远端”。
2. 本地项目仍使用原系统目录选择流程。
3. 远端项目弹窗可以在多台已配置电脑之间切换。
4. 目录列表和路径始终来自当前选择的远端电脑。
5. 添加后项目持久绑定连接 ID 和远端实际绝对路径。
6. 不同远端电脑可添加相同路径，同一电脑不能重复添加相同实际目录。
7. 连接删除后项目隐藏，恢复后使用原项目 ID 重新显示。
8. 连接禁用时项目不隐藏，但明确不可执行。
9. 整个流程不会把远端路径交给本机文件或命令接口。
10. 原有本地项目创建、归档、恢复和侧栏操作没有回归。

## 十二、阶段输出与下一阶段入口

本阶段输出稳定的“项目 → 执行目标”绑定关系和统一目标解析器。第三阶段以 `workspace_id` 为唯一业务入口，将文件、Git、工作树和终端接入对应执行目标。
