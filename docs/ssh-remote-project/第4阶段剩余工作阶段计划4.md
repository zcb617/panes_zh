# 第4阶段剩余工作阶段计划4：SSH 远端对话附件

## 一、文档定位

本文是第四阶段剩余工作的第 4 个实施计划。它在 Codex、OpenCode、Claude Code 三种远端文本对话已经可用后，为 SSH 远端项目补齐本机附件上传、发送和清理闭环。

## 二、阶段目标

本阶段结束后，用户可以沿用现有对话附件选择和预览入口，把本机附件发送给 SSH 远端项目中的三种 CLI。远端 CLI 只能收到上传后的远端缓存路径，不能收到本机路径。

## 三、业务范围

本阶段包含：

- 沿用现有附件选择、预览、大小和类型约束。
- 发送前把附件上传到线程所属远端机器。
- 远端缓存按 workspace/thread 隔离。
- 使用生成的安全文件名，原文件名只作为展示元数据。
- 校验上传字节数或摘要。
- 所有附件成功后才启动正式消息请求。
- Codex、OpenCode、Claude Code 使用各自协议读取远端路径。
- 上传失败、发送前断线和过期缓存的清理处理。

本阶段不包含：

- 改变现有支持的附件类型和大小上限。
- 跨 workspace 共享附件缓存。
- 运行时账号、用量、MCP、Skills 的统一展示。
- 手机端新增本地文件选择界面。

## 四、业务流程

```text
用户选择本机附件
  -> 现有预览和本机校验
  -> 根据 thread 解析 SSH workspace/connection
  -> 创建远端缓存目录
  -> 通过 SSH 标准输入上传
  -> 校验大小或摘要
  -> 将消息附件路径替换为远端路径
  -> 三种远端 CLI 的既有发送入口
```

缓存目录采用：

```text
~/.cache/panes/attachments/<workspace_id>/<thread_id>/
```

目录归属使用稳定的本地 workspace/thread ID，不能使用用户输入拼接任意远端路径。

## 五、主要工作

### 5.1 上传准备

- 后端重新读取 thread 和 workspace，不接受前端指定 connection ID 或远端目录。
- 校验本机文件存在、可读、大小和类型符合现有约束。
- 生成安全的远端文件名，禁止 `..`、绝对路径、目录分隔符和控制字符进入目标路径。

### 5.2 上传与校验

- 通过已有 SSH 标准输入数据通道上传，不建立公网文件服务。
- 创建目录时限制在 Panes 缓存根目录下。
- 上传后比较字节数或摘要；校验失败视为上传失败。
- 多附件逐个或受控并发上传，但只有全部成功才可发送消息。

### 5.3 CLI 发送适配

- 构造新的 turn attachment，`filePath` 必须是远端绝对缓存路径。
- Codex、OpenCode、Claude Code 各自只处理远端路径，不得执行本机路径兼容回退。
- 本地项目继续使用现有本机附件流程。

### 5.4 失败与清理

- 任一附件失败时，整次消息不进入 CLI。
- 已上传的同批临时文件尽力清理；清理失败不能改为发送部分附件。
- 会话结束、缓存过期或明确清理时，通过原 SSH 连接删除对应缓存。
- 连接不可达时保留待清理记录，下一次连接成功后重试；待清理失败不阻塞历史消息查看。

## 六、数据与迁移

若仅在 thread/message 现有附件元数据中保存远端路径和来源信息，不新增数据库结构。若需要持久化待清理任务或新增字段，必须先按 `docs/database-version-migration.md` 设计新版本迁移，不能修改已执行迁移。

不得把附件二进制内容写入现有 SQLite 数据库。

## 七、计划修改范围

计划修改或新增：

- `src-tauri/src/commands/chat.rs`：在 SSH 消息正式发送前增加统一附件上传步骤。
- `src-tauri/src/ssh/`：增加受限远端附件上传和清理能力，优先复用已有 SSH 标准输入通道。
- 三种 SSH 远端 engine 适配：接收已转换的远端附件路径。
- `src/components/chat/ChatPanel.tsx`、附件预览/错误相关组件和 `src/stores/chatComposerStore.ts`：展示上传中及失败状态。
- `src/lib/ipc.ts` 及附件类型。
- 对应 Rust、TypeScript 和端到端测试。
- 只有确需持久化待清理状态时，才新增数据库迁移与清单登记。

明确不修改：

- 本地项目附件发送语义。
- SSH tunnel Map 和 CLI 服务生命周期 key。
- 第三阶段普通远端文件工作区业务。
- 现有附件上限，除非用户另行确认。

## 八、异常与安全

界面至少区分：本机文件不存在、类型不支持、文件过大、SSH 连接不可达、远端目录创建失败、上传中断、校验失败、远端空间不足、缓存清理失败。

远端路径必须由后端生成并限制在缓存根目录内。日志可以记录文件大小和生成路径，但不得记录附件正文或敏感内容。

## 九、测试重点

- 单个和多个附件。
- 空格、中文、重复文件名和特殊字符。
- 文本及现有支持的图片类型。
- 文件过大、上传中断、校验失败、发送前断线。
- 三种远端 CLI 收到的均为远端路径。
- 同一 thread 重复发送及不同 workspace/thread 目录隔离。
- 清理成功、离线待清理和恢复后重试。
- 本地项目附件回归。

## 十、验收标准

1. 三种 SSH 远端 CLI 均能读取已上传附件并正常回复。
2. 远端 CLI 请求中不存在 Windows 本机路径或其他本机附件路径。
3. 任一附件上传失败时，本次消息不会发送，界面显示明确原因。
4. 多项目、多线程附件缓存相互隔离。
5. 文件名不能逃逸 Panes 远端缓存目录。
6. 可清理缓存正常删除；离线清理失败不会破坏历史消息。
7. 本地项目附件行为保持不变。

## 十一、阶段输出与下一阶段入口

本阶段输出三种远端 CLI 共用的安全附件前置上传闭环。计划 5 只完善目标机器运行时信息和输入框联动，不改变附件的目标解析、上传顺序和失败规则。
