# 第五阶段：智能体运行工具设计

> 状态：暂缓，不作为当前执行项。
>
> 暂缓说明：用户已明确本阶段不影响当前 SSH 远端项目使用，先放到后面再评估。本文中的智能体运行工具按机器分组、远端扫描、远端安装、远端启动管理和相关入口改造均不在当前阶段执行；后续只有用户重新明确要求时，才重新确认边界并推进。

## 一、阶段目标

改造主界面的“智能体运行工具”页面，按执行机器分组展示当前 Panes 支持的全部 CLI/智能体：先显示“本地”，再按连接设置中的顺序显示“远端 1、远端 2……”。每组独立展示安装状态、版本、检测错误和可执行操作。

智能体的实际启动目标仍由左侧当前选中的项目决定。机器分组只负责展示状态，不成为第二个目标选择器，也不能绕过项目与 SSH 连接的绑定关系。

## 二、业务范围

本阶段包含：

- 智能体运行工具页面按本地和每条 SSH 连接分组。
- 每台机器独立扫描当前 Panes 支持的全部工具。
- 独立展示安装状态、版本和错误。
- 根据当前项目启用对应机器分组的启动按钮。
- 在当前项目的本地终端或 SSH 终端中启动智能体。
- 启动参数按机器和工具隔离。
- 远端安装命令在当前远端项目终端中执行。
- 命令面板、项目启动配置等其他启动入口遵守相同目标规则。

本阶段不包含：

- 从智能体页面选择或创建项目。
- 点击机器分组后切换当前项目。
- 在没有对应项目的情况下直接打开一台远端电脑的任意终端。
- 为不同智能体分别实现 SSH 连接方式。
- 改变某个工具自身的安装命令或产品能力。

## 三、概要设计

### 3.1 页面入口

保留现有主界面“智能体”入口和 `HarnessPanel` 全页布局，不新建第二个页面。现有单一工具列表改为机器分组列表。

计划主要改造：

- `src/components/onboarding/HarnessPanel.tsx`
- `src/components/onboarding/HarnessLaunchSettingsModal.tsx`
- `src/stores/harnessStore.ts`
- `src/components/shared/CommandPalette.tsx`
- `src/components/layout/ThreeColumnLayout.tsx` 保持现有页面挂载方式
- 后端 `src-tauri/src/commands/harness.rs`

### 3.2 分组结构

页面顺序固定为：

```text
本地
SSH 连接列表中的第 1 台远端电脑
SSH 连接列表中的第 2 台远端电脑
……
```

已删除连接不展示。禁用连接继续展示，以便用户看到其工具状态缓存，但组标题标记“连接已禁用”，刷新和启动不可用。连接恢复后使用原连接 ID 恢复原分组状态和缓存身份。

### 3.3 工具范围

每组展示当前 Panes 已登记的完整工具目录，而不是只支持对话阶段的三个 engine。当前界面中的工具包括：

- Codex CLI
- Claude Code
- Gemini CLI
- Antigravity CLI
- Kiro
- OpenCode
- Kilo Code
- Factory Droid

后续工具仍由现有工具目录统一登记；机器分组自动读取目录，不在页面再维护一份硬编码分支。

## 四、页面详细设计

### 4.1 页面标题区

标题继续使用“智能体运行工具”。副标题调整为当前已完成扫描的机器数量和工具数量，例如“已检测 3 台机器，共发现 12 个已安装工具”。

右上角保留刷新按钮：

- 点击后刷新所有可用机器。
- 已禁用或不可达机器返回各自状态，不阻塞其他分组。
- 同一机器同一时刻只执行一个扫描任务。

### 4.2 机器分组标题

每个分组标题显示：

- 本地或 SSH 连接显示名称。
- 远端时显示 `user@host` 摘要。
- 当前项目所在机器显示“当前项目”标记。
- 已安装数量/工具总数。
- 扫描中、可用、不可达、已禁用等状态。
- 单独刷新该分组的按钮。

分组可以折叠，但折叠状态只影响界面，不停止当前扫描。默认展开当前项目分组；其他分组首次进入页面时也展示工具状态，之后记住用户的折叠选择。

### 4.3 工具卡片

每个工具继续使用现有卡片结构，展示：

- 图标和名称。
- 原生标记（如适用）。
- 工具说明。
- 已安装/未安装。
- 版本。
- 检测错误或版本不兼容提示。
- 启动设置。
- 启动、安装、复制命令和官网等现有操作。

卡片的 DOM、交互和样式作为完整组件维护；不要把孤立的位置补偿样式抽到不同分组共用。

### 4.4 启动按钮状态

只有当前选中项目所属机器分组的启动按钮可以执行：

- 当前项目是本地项目：仅“本地”组可启动。
- 当前项目是远端项目：仅该项目绑定连接的分组可启动。
- 当前没有项目：所有启动按钮禁用。
- 当前项目连接已禁用、已删除或不可达：对应按钮禁用并展示原因。

其他分组仍显示工具状态，但启动按钮禁用，悬停提示“请先选择该机器上的项目”。

点击分组、卡片或禁用按钮都不能改变当前项目，也不能把当前项目的命令发到该分组机器。

### 4.5 扫描过程

进入页面时：

1. 加载本地目标和未删除 SSH 连接。
2. 先展示上次缓存结果。
3. 本地目标调用本机扫描。
4. 各启用远端连接通过统一 SSH 命令通道扫描。
5. 每个结果带 target key 和请求序号回写。
6. 页面按分组独立更新。

远端扫描获取工具路径和版本，不通过本机 PATH 推断远端安装状态。连接不可达时保留上次结果并标记“上次检测结果”，不能把缓存结果显示为当前已连接。

### 4.6 启动智能体

用户点击当前项目组中的“启动”：

1. 前端提交当前 workspace ID、harness ID 和该机器对应的启动参数。
2. 后端从 workspace ID 解析执行目标。
3. 后端校验解析出的 target 与卡片 target 一致；不一致直接拒绝。
4. 后端根据目标机器的扫描目录生成启动命令。
5. 前端切回当前项目的终端表面。
6. 创建该项目的终端 session。
7. 本地项目在本地 PTY 中运行；远端项目在 SSH PTY 中运行。
8. 把启动命令写入新终端。

启动行为继续沿用现有 Panes 的“在终端启动”，不另起不可见后台服务。远端工具运行目录为当前项目根目录或当前活动工作树。

### 4.7 安装工具

当前页面已有“在终端安装”和“复制命令”能力，远端项目按以下方式处理：

- 当前远端项目组点击“安装”，在该项目 SSH 终端中写入现有安装命令。
- 复制命令只复制文本，不执行，任何分组均可使用。
- 非当前项目组的“在终端安装”禁用，避免命令写入错误机器。
- 安装结束后由用户点击该组刷新，或在终端进程结束事件可可靠识别时触发一次扫描。

Panes 不把工具安装到本机后宣称远端已安装，也不自动获取远端管理员权限。

### 4.8 启动设置

不同机器可能安装不同版本，支持的启动参数也可能不同。因此启动设置按以下键保存：

```text
(ExecutionTarget, harness_id)
```

打开设置弹窗时显示机器名称。保存本地工具参数不会覆盖远端同名工具参数；删除并恢复 SSH 连接时因连接 ID 不变，原远端启动设置仍能恢复。

## 五、其他启动入口

### 5.1 命令面板

命令面板中的已安装智能体列表只使用当前项目目标的扫描结果：

- 当前是本地项目，显示本地已安装工具。
- 当前是远端项目，显示该远端已安装工具。
- 执行时仍提交 workspace ID，并由后端重新解析目标。

不能因为智能体页面曾扫描到其他机器工具，就在命令面板中把它列为当前项目可启动。

### 5.2 项目启动配置

第三阶段已经保证启动配置在项目目标终端执行。本阶段补充工具能力校验：

- 启动配置引用智能体命令时，检测当前项目机器的安装状态。
- 未安装时提示当前机器缺少工具。
- 不以本机安装状态替代远端检测。

### 5.3 页面启动设置快捷入口

工具卡片的启动设置只编辑该机器对应工具。打开弹窗期间如果当前项目切换到另一机器，弹窗保留原 target 标识；保存仍写回原 target，但“立即启动”必须重新校验当前项目，不允许跨目标启动。

## 六、数据与状态设计

### 6.1 前端状态

`harnessStore` 调整为：

```text
targets
harnessesByTarget
scanStateByTarget
scanErrorByTarget
lastScannedAtByTarget
launchArgsByTargetAndHarness
```

target key 由后端生成并稳定返回：本地使用固定 local，远端使用连接 UUID，不使用可修改的显示名称。

### 6.2 缓存失效

以下情况使目标工具缓存失效或标记过期：

- 用户主动刷新。
- SSH 连接参数编辑。
- 连接禁用、删除、恢复或启用。
- 目标终端完成工具安装后。
- 应用版本升级导致工具检测规则变化。

删除连接不物理删除以连接 ID 为键的启动设置；页面只隐藏该目标。恢复原 ID 后重新显示。

## 七、后端接口设计

| 命令 | 用途 |
| --- | --- |
| `list_harness_targets` | 返回本地和未删除 SSH 目标摘要 |
| `scan_harnesses_for_target` | 扫描指定展示目标的全部工具 |
| `get_harness_launch_settings` | 读取目标和工具对应参数 |
| `save_harness_launch_settings` | 保存目标和工具对应参数 |
| `resolve_harness_launch` | 根据 workspace ID 生成目标内启动命令 |

扫描接口可以接收 target key，因为页面业务就是查看指定机器状态；启动接口必须接收 workspace ID 并从项目重新解析目标，不能仅凭 target key 执行。

后端扫描实现：

- Local 调用现有本机工具检测。
- Ssh 通过统一 SSH `exec` 执行同一工具目录声明的检测命令。
- 解析为相同 `HarnessInfo` DTO，并附加 target key。
- 各工具只声明检测和启动方式，不持有自己的 SSH 客户端。

## 八、错误处理

每个机器分组独立显示错误：

- 连接已禁用或删除。
- SSH 不可达。
- 远端 shell 不兼容。
- 工具未安装。
- 版本命令失败或版本无法解析。
- 工具版本不兼容。
- 当前项目不属于该机器。
- 当前没有项目。
- 终端创建或命令写入失败。

一个分组失败不能让其他分组消失。错误恢复后刷新对应组即可，不要求重启应用。

## 十、测试设计

### 10.1 分组与扫描测试

- 本地始终第一组，远端按连接顺序展示。
- 删除连接隐藏分组，恢复原 ID 后重新显示。
- 禁用连接显示但不能扫描或启动。
- 两台远端的安装状态和版本互不覆盖。
- 单组失败不影响其他组。
- 旧请求不能覆盖刷新后的新结果。

### 10.2 启动测试

- 本地项目只能启动本地组工具。
- 远端项目只能启动绑定连接组工具。
- 非当前机器组按钮正确禁用。
- 远端启动命令进入当前项目 SSH 终端和正确目录。
- 前端伪造 target key 被后端 workspace 校验拒绝。
- 连接中断时不在本机启动同名工具。

### 10.3 设置与其他入口测试

- 启动参数按目标和工具隔离。
- 命令面板只列当前项目目标的工具。
- 项目启动配置使用目标机器检测结果。
- 切换项目后各入口同步改变可启动工具。

### 10.4 本地回归

- 本地智能体扫描、安装、复制命令、启动和官网入口保持现有行为。
- 原有终端启动方式和工具卡片信息不丢失。

## 十一、阶段验收标准

1. 智能体页按“本地、远端 1、远端 2……”逐一展示。
2. 每组完整显示当前支持的全部工具、安装状态、版本和检测错误。
3. 页面能单独或整体刷新机器状态，一个远端失败不影响其他组。
4. 只有当前项目所在机器分组可以启动或在终端安装工具。
5. 远端工具在当前远端项目的 SSH 终端和项目目录中启动。
6. 分组本身不会切换项目，也不能成为第二个执行目标选择器。
7. 启动设置按机器和工具隔离。
8. 命令面板和项目启动配置遵守同一目标规则。
9. 删除并恢复连接后因 ID 不变，原分组身份和启动设置可以恢复。
10. 任何远端错误都不会改为启动本机同名工具。
