# 第六阶段：定时任务管理设计

> 状态：暂缓，不作为当前执行项。
>
> 暂缓说明：用户已明确当前不需要远端定时任务管理，本阶段先不做。本文中的远端定时任务创建、执行、暂停恢复、运行记录、数据库迁移和调度器改造均不在当前阶段执行；后续只有用户重新明确要求时，才重新评估是否恢复。

## 一、阶段目标

让绑定远端项目的定时任务到点后，通过该项目所在远端电脑的 CLI 执行。SSH 连接禁用或删除时，关联任务进入可恢复暂停状态；连接恢复并启用后，任务保留原 ID、配置和执行记录，从当前时间重新计算下次执行，不补跑暂停期间的任务。

本阶段不新建第二套远端调度器。本机 Panes 仍负责到点触发，真正的消息执行目标由任务所属项目解析。

## 二、业务范围

本阶段包含：

- 创建和编辑定时任务时展示项目的本地/远端目标。
- 远端项目的新线程任务和已有线程任务。
- 到点后复用第四阶段统一消息发送入口。
- 远端任务状态、运行错误和执行记录展示。
- 连接禁用、删除、恢复和启用引起的任务暂停/恢复。
- 任务用户启用状态与连接暂停状态分离。
- 从当前时间计算恢复后的下一执行时间，不补跑。
- 多台远端电脑的任务隔离。

本阶段不包含：

- 把调度器部署到远端电脑。
- Panes 未运行时由远端独立执行任务。
- 使用 `execution_device_id` 保存 SSH 连接 ID。
- 连接临时不可达时自动转为本机执行。
- 永久删除连接、项目、对话、任务或执行记录。

## 三、概要设计

### 3.1 调度与执行分离

现有调度器继续运行在本机 Panes：

```text
本机调度器发现到期任务
          │
          ▼
scheduled_task.workspace_id
          │
          ▼
ExecutionTargetResolver
      ├── Local → 本机 CLI
      └── Ssh   → 远端 CLI + SSH 隧道
```

`execution_device_id` 继续表示负责触发任务的 Panes 设备。它不表示项目执行机器，不能写入 `ssh_connection_id`。SSH 目标始终从 workspace ID 解析。

### 3.2 页面位置

保留现有主界面“定时任务”入口和 `ScheduledTasksPage`。不按机器拆成多套任务页面，任务列表继续围绕业务任务展示，但增加目标信息和暂停状态。

每条任务显示：

- 任务说明。
- 所属项目和线程目标。
- “本地”或 SSH 连接显示名称。
- 用户启用开关。
- 正常、连接暂停、执行中、成功或失败状态。
- 下次执行时间。
- 最近一次执行结果。

## 四、创建与编辑详细设计

### 4.1 选择项目

创建定时任务时继续选择项目。项目选项增加目标标记：

- 本地项目显示“本地”。
- 远端项目显示连接名称。
- 已禁用连接的远端项目仍可看到，但标注“连接已禁用”；允许保存任务，任务保存后处于连接暂停状态。
- 已删除连接的项目因第二阶段规则从普通项目列表隐藏，不能创建新任务。

用户选择项目后不能再单独选择一台 SSH 机器，避免任务目标与项目目标不一致。

### 4.2 目标线程

现有两种任务目标保持不变：

- 已有线程：任务绑定指定 thread ID，线程必须属于所选 workspace。
- 新线程：每次或首次执行时按现有产品行为在所选 workspace 创建线程。

后端保存前验证线程和 workspace 关系。前端不能提交另一项目的 thread ID。

### 4.3 保存任务

保存流程：

1. 校验说明、提示词、项目、线程目标和计划配置。
2. 根据 workspace ID 解析项目类型。
3. 保存任务原有业务字段。
4. 若远端连接已禁用，则同时设置连接暂停信息；用户的 `enabled` 值照常保存。
5. 若目标可用，计算下一次执行时间。
6. 返回完整任务 DTO 和目标摘要。

编辑计划、提示词或用户启用状态不会改变 workspace、thread 和 connection ID。用户主动关闭任务时只设置 `enabled = false`，不能伪装为连接暂停。

## 五、到期执行详细设计

### 5.1 到期查询

调度器只选择满足以下条件的任务：

```text
enabled = 1
AND suspended_at IS NULL
AND archived_at IS NULL
AND next_run_at <= now
```

对于远端项目，查询或领取执行权时还要确认连接记录未删除且启用，避免连接状态变更与调度并发导致任务误执行。

到期任务需要沿用现有互斥或租约机制，保证同一任务同一触发点只创建一条运行记录。

### 5.2 执行已有线程任务

1. 调度器创建 `scheduled_task_run`，状态为运行中。
2. 读取任务绑定 thread ID。
3. 由统一发送入口从 thread 查询 workspace。
4. 解析本地或 SSH 目标。
5. 远端项目获取对应目标的 engine 运行时和 SSH 隧道。
6. 发送任务提示词并接收流式结果。
7. 更新线程消息和任务运行记录。
8. 计算下一次执行时间。

### 5.3 执行新线程任务

1. 调度器创建运行记录。
2. 在任务 workspace 中创建线程，线程 ID 使用现有稳定生成方式。
3. 新线程继承任务配置的 engine、模型和权限，且必须用该 workspace 目标机器的能力校验。
4. 进入与普通消息相同的发送入口。
5. 成功后把新 thread ID 记录到运行详情，供用户直接打开。

不能先在本机创建 CLI 会话再把消息转向远端；线程建立和 CLI 会话都从项目目标开始。

### 5.4 成功与失败

成功时：

- 运行记录保存完成时间、结果摘要和关联线程。
- 任务计算下一次执行时间。

临时失败时：

- 运行记录保存结构化错误和可读说明。
- 任务本身保持用户原 `enabled` 状态。
- 按正常计划计算下一次执行时间。
- 不自动暂停、不自动禁用、不在本机补执行。

临时失败包括 SSH 超时、远端 CLI 退出、隧道中断、账号未登录或用量不足。连接明确被禁用或删除则走暂停流程，而不是普通运行失败。

## 六、连接暂停与恢复详细设计

### 6.1 暂停字段

`scheduled_tasks` 增加：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `suspended_at` | TEXT | 因连接状态暂停的时间 |
| `suspension_reason` | TEXT | `ssh_connection_disabled` 或 `ssh_connection_deleted` |
| `suspended_by_connection_id` | TEXT | 触发暂停的连接 ID |

用户启用状态仍保存在现有 `enabled`。连接操作不能覆盖它。

### 6.2 禁用 SSH 连接

用户在设置页禁用连接时，在同一业务操作中：

1. 保存连接 `enabled = false`。
2. 找到所有通过 workspace 关联该连接的未归档任务。
3. 写入 `suspended_at`、`ssh_connection_disabled` 和连接 ID。
4. 停止这些任务参与到期查询。
5. 关闭连接运行时和隧道。

原来 `enabled = false` 的任务也可以记录连接暂停，但恢复时仍保持用户禁用。

### 6.3 删除 SSH 连接

软删除连接时：

1. 保存原连接 ID 和原 `enabled` 状态，只写 `deleted_at`。
2. 关联项目从普通项目列表隐藏。
3. 关联任务写入 `ssh_connection_deleted` 暂停原因。
4. 已存在的任务、线程、消息和运行记录全部保留。
5. 已经领取但尚未开始发送的运行需要在目标二次校验时停止，并记录“连接已删除”。

若任务先因禁用暂停、随后连接被删除，暂停原因更新为 deleted；`suspended_by_connection_id` 不变。

### 6.4 恢复连接

恢复软删除连接时：

- 清空连接 `deleted_at`，连接 ID 不变。
- 连接删除前若为启用状态，则触发检测；检测和启用成功后恢复任务。
- 连接删除前若已禁用，恢复后仍禁用，任务保持暂停。
- 只处理 `suspended_by_connection_id` 等于该连接的任务。
- 用户主动禁用的任务仍保持 `enabled = false`。

### 6.5 重新启用连接

连接从禁用改为启用并通过基本状态校验后：

1. 查找由该连接暂停且连接不再删除的任务。
2. 清空暂停字段。
3. 以当前时间为基准计算每个任务的下一次未来触发点。
4. 不创建暂停期间的运行记录。
5. 不补跑任何已错过触发点。

例如每天 09:00 的任务在 10:00 恢复，下次执行为下一天 09:00，不立即补跑当天 09:00。

### 6.6 并发一致性

连接状态变更、任务暂停和恢复应在数据库事务中完成。调度器在真正发送消息前再次读取任务、连接和 workspace 状态，解决到期查询与用户操作并发窗口。

同一个任务重复收到暂停或恢复操作必须幂等，不能重复修改用户启用值或生成多条运行记录。

## 七、数据与 ID 保持

以下 ID 在连接禁用、删除和恢复过程中保持不变：

```text
ssh_connection_id
workspace_id
thread_id
message_id
scheduled_task_id
scheduled_task_run_id
engine_thread_id
```

连接软删除不会触发数据库级联删除。任务运行记录继续引用原任务和线程。恢复只改变连接可见性、任务暂停字段和未来的 `next_run_at`。

## 八、页面详细设计

### 8.1 任务列表

远端任务卡片增加连接标识。状态展示优先级：

1. 连接已删除导致暂停。
2. 连接已禁用导致暂停。
3. 用户已禁用。
4. 正在执行。
5. 最近失败。
6. 等待下次执行。

连接暂停状态下启用开关仍反映用户 `enabled`，不能把开关自动关掉。状态旁显示“恢复连接后继续”，并提供跳转到设置 → 连接的入口。

### 8.2 任务详情和运行记录

任务详情显示：

- 项目名称和执行目标。
- engine、模型和权限摘要。
- 计划表达。
- 用户启用状态。
- 连接暂停原因和时间。
- 下次执行时间；暂停时显示“—”。
- 历史运行记录。

远端运行失败记录显示目标连接名称和分类错误，但不泄露私钥、临时认证密钥或完整敏感命令。

### 8.3 从运行记录打开线程

点击运行记录中的线程仍按 workspace/thread ID 打开原项目。若连接已删除，项目当前隐藏，则提示先恢复连接；不能把线程临时挂到本地项目打开。

## 九、后端接口设计

现有任务 CRUD 接口保持业务含义，DTO 增加目标和暂停字段。主要调整：

| 接口或模块 | 调整 |
| --- | --- |
| 创建/更新任务 | 校验 workspace/thread 关系和连接状态 |
| 任务列表 | 返回目标摘要和暂停信息 |
| 到期查询 | 排除 suspended，并校验远端连接 |
| 任务执行器 | 调用第四阶段统一发送入口 |
| 连接禁用/删除 | 批量暂停关联任务 |
| 连接恢复/启用 | 清除匹配暂停并重算 next run |
| 运行记录 | 保存远端错误和关联线程 |

连接管理命令和任务仓库之间的调用放在业务服务层或事务函数内，避免界面先改连接、再发第二个请求暂停任务形成不一致。

## 十、前端状态设计

`scheduledTaskStore` 继续保存任务和运行记录，增加：

```text
targetSummary
suspendedAt
suspensionReason
suspendedByConnectionId
connectionState
```

收到连接状态变化事件时，刷新受影响任务。任务状态更新按 task ID 合并，旧执行事件不得覆盖连接暂停后的新状态。

## 十二、测试设计

### 12.1 调度测试

- 本地任务继续由本机 CLI 执行。
- 远端已有线程任务由原线程目标远端 CLI 执行。
- 远端新线程任务在目标 workspace 创建线程并执行。
- 多台远端相同计划、相同 engine 不串运行时。
- 到期查询不选择用户禁用、连接暂停或归档任务。

### 12.2 暂停恢复测试

- 禁用连接批量暂停关联任务，`enabled` 不变。
- 删除连接更新暂停原因为 deleted，全部数据和 ID 保留。
- 恢复但仍禁用时任务不恢复。
- 启用后只恢复由该连接暂停的任务。
- 用户禁用任务恢复连接后仍禁用。
- 下一次触发从当前时间计算，不补跑。
- 重复暂停和恢复幂等。

### 12.3 失败测试

- SSH 临时超时只产生失败运行，不自动暂停。
- CLI 未安装、未登录、隧道中断和用量不足均保存明确错误。
- 连接在任务领取后、发送前删除时二次校验能阻止执行。
- 任意远端失败都不调用本机 CLI。

### 12.4 数据保持测试

- 删除恢复前后连接、项目、线程、消息、任务和运行记录 ID 不变。
- 项目因连接删除隐藏后，任务和运行记录仍可从数据库恢复。
- 迁移旧任务时暂停字段为空，原计划和运行记录不变。

### 12.5 本地回归

- 本地任务创建、编辑、启用、禁用、执行和历史记录保持现有行为。
- `execution_device_id` 的现有设备调度语义不变。

## 十三、阶段验收标准

1. 创建或编辑任务时能清楚看到项目属于本地还是哪台远端电脑。
2. 远端项目已有线程任务和新线程任务都由对应远端 CLI 执行。
3. `execution_device_id` 仍只表示触发设备，不保存 SSH 连接。
4. 禁用或删除连接后，关联任务停止参与到期查询，但用户启用状态不变。
5. 恢复并启用连接后，任务原 ID、配置和历史执行记录全部保留。
6. 恢复后从当前时间计算下一次未来执行，不补跑暂停期间任务。
7. 临时网络或 CLI 错误形成失败运行记录，不自动转本地、不自动禁用。
8. 多台远端任务和本地任务互不影响。
9. 连接状态变化与调度并发时不会误执行或重复执行。
10. 原有本地定时任务功能没有回归。
