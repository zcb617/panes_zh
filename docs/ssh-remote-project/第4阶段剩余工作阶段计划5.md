# 第4阶段剩余工作阶段计划5：远端运行时信息与输入框联动

## 一、文档定位

本文是第四阶段剩余工作的第 5 个实施计划。前三个对话闭环已经具备各自发送所需的最小模型和权限能力；本阶段把健康、模型、思考强度、权限、账号、用量、MCP、Skills 和扩展能力统一收口为按目标机器隔离的用户界面状态。

## 二、阶段目标

本阶段结束后，用户切换本地项目或不同 SSH 远端项目时，对话输入框及运行时信息区域会准确显示该项目所在机器的 CLI 能力，不会沿用上一台机器或本机的缓存。

## 三、业务范围

本阶段包含：

- 后端返回稳定的 ExecutionTarget key 和连接显示信息。
- engine 列表、健康、模型、账号、用量和能力查询带 workspace/thread 上下文。
- 前端缓存按 `(targetKey, engineId)` 隔离。
- 模型、思考强度和权限随当前项目目标切换。
- MCP、Skills、Plugin、Agent、Command 等现有 CLI 能力按目标机器查询；Codex Apps（连接器）是用户明确要求去掉的内容，不查询、不缓存、不展示。
- 连接状态变化后仅失效对应目标缓存。
- 页面明确标识信息来自本机还是哪条 SSH 连接。

本阶段不包含：

- 新增第五阶段的“智能体运行工具”整页按机器分组功能；总计划第五阶段当前已暂缓，不作为当前执行项。
- 改变三个 CLI 已完成的消息协议。
- 手机入口和多机器异常综合收口。
- Codex Apps（连接器）：这是用户明确要求去掉的能力项，本阶段不查询、不缓存、不展示。

## 四、目标状态结构

后端目标身份必须稳定，不能由前端使用显示名称拼接。前端状态按以下语义组织：

```text
enginesByTarget[targetKey]
healthByTargetAndEngine[targetKey][engineId]
modelsByTargetAndEngine[targetKey][engineId]
usageByTargetAndEngine[targetKey][engineId]
accountByTargetAndEngine[targetKey][engineId]
capabilitiesByTargetAndEngine[targetKey][engineId]
```

本机和 SSH 目标必须使用不同 key；两台 SSH 主机即使显示名称相同，也必须使用不同 key。

## 五、主要工作

### 5.1 项目切换

1. 用户切换 workspace 或 thread。
2. 前端把 workspace/thread 上下文传给运行时查询接口。
3. 后端解析目标并返回稳定 target key、目标类型和连接显示名称。
4. 前端读取该 target 下的 engine、健康和能力缓存。
5. 缓存不存在或已失效时请求目标机器。
6. 迟到响应只能写入发起请求时的 target，不能覆盖当前活动项目。

### 5.2 模型与思考强度

- 模型列表来自目标机器上的 CLI。
- 切换模型后按目标机器、engine 和模型重新计算思考强度。
- 已保存值不再支持时，展示并采用远端模型默认值。
- 发送前仍由后端再次校验，前端缓存不能作为最终权限依据。

### 5.3 权限和审批能力

- 仅展示目标 CLI 支持的权限与 sandbox 模式。
- 审批决定选项与原 thread 的 engine/target 一致。
- 不支持的权限模式不能仅靠隐藏处理；后端发送前也要拒绝。

### 5.4 健康、账号、用量和扩展能力

- 健康检查反映目标机器上的 CLI、版本、登录和协议状态。
- 账号与用量数据按目标隔离，查询失败不使用其他目标的旧数据填充。
- Codex Skills、Codex Plugins、OpenCode Agent/Command/MCP、Claude 相关能力均携带目标和项目 cwd；Codex Apps（连接器）按用户要求去掉，不参与查询和展示。
- 页面显示“本机”或 SSH 连接显示名称，便于用户确认数据来源。

### 5.5 缓存失效

- SSH 连接禁用、删除、重连或远端服务重启时，使对应 target 缓存失效。
- 用户主动刷新只刷新当前目标。
- 切换项目保留其他目标缓存，但迟到结果必须按 target 归档。

## 六、计划修改范围

计划修改或新增：

- `src-tauri/src/commands/engines.rs`：为 engine、健康、模型、用量和能力接口增加 workspace/thread 上下文。
- 三种 SSH 远端 engine 适配：补齐目标机器能力查询。
- `src-tauri/src/models.rs`：增加稳定 target 描述和目标化返回 DTO。
- `src/stores/engineStore.ts`：从按 engine 缓存调整为按 target + engine 缓存。
- `src/stores/chatComposerStore.ts`：保存各 workspace/thread 的选择，并与目标能力校验。
- `src/components/chat/ModelPicker.tsx`、`PermissionPicker.tsx`、`CodexRuntimePicker.tsx`、`ChatPanel.tsx`：按目标展示状态和来源。
- `src/lib/ipc.ts` 及相关类型、监听和测试。

明确不修改：

- 第五阶段的智能体运行工具页面；总计划第五阶段当前已暂缓，不作为当前执行项。
- 本地 engine 的实际执行语义。
- tunnel Map 和远端服务按机器共享规则。
- 已完成的三个 CLI 消息归属规则。

## 七、异常与兼容

界面至少区分：目标连接不可用、CLI 未安装、版本不兼容、账号未登录、模型目录读取失败、用量查询失败、能力查询失败、保存模型已失效。

单项信息失败时可以保留其他已成功信息，但不得引用本机或另一台远端机器的数据作为后备。

## 八、测试重点

- 本地、远端 A、远端 B 的 engine、健康、模型、账号和用量隔离。
- 同 engine、同模型 ID 在不同目标下分别展示和发送。
- 快速切换项目时迟到响应不覆盖当前目标。
- 模型切换后思考强度重算。
- 连接禁用、重连和主动刷新时缓存精确失效。
- MCP、Skills、Plugin、Agent、Command 等目录携带正确 cwd/target；Codex Apps（连接器）按用户要求不展示，不列入测试项。
- 本地输入框与三个远端对话闭环回归。

## 九、验收标准

1. 切换本地、远端 A、远端 B 项目时，模型、思考强度和权限同步切换。
2. 页面明确显示当前运行时来自本机或哪条 SSH 连接。
3. 健康、账号、用量、MCP、Skills 和扩展能力不会跨目标覆盖。
4. 快速切换项目后，迟到请求不会污染当前项目界面。
5. 目标机器不支持的模型或权限不能发送。
6. 远端查询失败不会显示本机或其他远端目标的数据。
7. 本地项目现有输入框行为保持不变。

## 十、阶段输出与下一阶段入口

本阶段输出完整的目标化运行时信息和输入框状态。第四阶段剩余工作在计划 5 完成后收口；原计划 6 已取消，不再进入多机器并行、断线恢复、连接清理和手机统一入口的独立收口计划。
