# 第4阶段剩余工作阶段计划3：SSH 远端 Claude Code 对话闭环

## 一、文档定位

本文是第四阶段剩余工作的第 3 个实施计划。它在计划 1、计划 2 已稳定的执行目标和机器级服务契约上，把当前仅用于会话扫描的远端 Claude 适配能力扩展为正式文本对话能力。

## 二、阶段目标

本阶段结束后，用户可以在 SSH 远端项目中创建或恢复 Claude Code 会话，通过绑定机器上的 Claude Code 完成文本对话、流式接收、取消和审批。

## 三、业务范围

本阶段包含：

- 同一远端主机只运行一个 `hostId + claude` 服务入口。
- 每次 Claude `query` 携带当前项目 `cwd`。
- 支持新会话、恢复已同步会话、文本发送、流式事件、取消和审批。
- 模型、思考强度、权限及健康信息来自远端 Claude Code 环境。
- 远端 Claude 适配器按应用版本安装、校验和复用。
- 远端缺少 Node.js、Claude Code、SDK 依赖或登录状态时给出明确错误。
- 不使用本机 Claude Code 或本机 Claude sidecar 作为远端失败后的替代。

本阶段不包含：

- 本机附件上传。
- 全部运行时信息的统一展示和缓存收口。
- 手机入口和多机器综合验收。

## 四、适配器结构

当前 `claude-remote-session-server.mjs` 只提供健康检查和会话扫描。本阶段应让远端 Claude 服务同时承载会话扫描和正式对话，或由同一 `hostId + claude` 服务入口统一路由这两类能力。

```text
Panes
  -> SSH tunnel 本机入口
  -> 远端 Claude Panes 适配服务
     -> /health
     -> /sessions?cwd=...
     -> query/stream/cancel/approval 协议
  -> 远端 Claude Code / Agent SDK
```

适配器必须只监听远端 `127.0.0.1`。项目上下文由每次 query 的 `cwd` 提供，服务启动时不得绑定 workspace。

## 五、主要工作

### 5.1 远端适配器能力扩展

- 复用现有 Claude Agent SDK 协议语义，增加可通过 SSH tunnel 使用的正式对话传输。
- 定义 query、流式事件、取消、审批回复、模型/运行时信息和健康检查的请求响应。
- 每条事件包含可路由的 query/session 身份，Panes 再映射为 workspace/thread。
- 会话扫描和正式对话共用同一机器级服务生命周期。

### 5.2 版本安装与启动

- 以适配器和依赖内容版本确定远端安装目录。
- 相同版本完整存在时直接复用，不覆盖正在运行的目录。
- 上传后校验关键文件和依赖完整性，再切换为可启动版本。
- 远端服务只绑定回环地址，并由现有 Registry 统一启动、等待和关闭。

### 5.3 新建、恢复和发送

- query 必须携带 workspace 的远端根目录。
- 已同步 Claude session 通过原 engine thread ID 恢复。
- 远端 session 缺失或 cwd 不一致时阻止恢复。
- 远端 SDK 产生的文本、thinking、工具、审批、用量和完成事件映射为现有聊天事件。

### 5.4 取消、审批和生命周期

- 取消和审批按原 query/session 路由到同一远端服务。
- 每次正式 turn 建立 `hostId + claude + threadId` 持续占用。
- turn 结束、取消或失败后释放相同凭证。
- 释放不得关闭其他项目正在使用的 Claude 服务。

## 六、计划修改范围

计划修改或新增：

- `src-tauri/sidecar/claude-remote-session-server.mjs` 及构建产物来源：扩展正式对话协议。
- `src-tauri/src/engines/`：新增 SSH 远端 Claude 客户端或目标运行时适配。
- `src-tauri/src/commands/chat.rs`：启用 SSH Claude 发送、取消和审批分支。
- `src-tauri/src/commands/engines.rs`：远端 Claude 模型和健康查询。
- `src-tauri/src/ssh/cli_tunnel_registry.rs`：完善 Claude 适配器安装校验、启动和就绪检查。
- `scripts/build-claude-sidecar.mjs`：如远端适配器打包内容发生变化，同步调整构建清单。
- Claude 输入框、模型、权限及聊天状态相关前端模块。
- `tests/claudeRemoteSessionServer.test.mjs` 及对应 Rust、TypeScript 测试。

明确不修改：

- 本机 Claude sidecar 的业务行为，除非提取的是不改变本地语义的纯协议结构。
- 本机 Claude 会话发现和发送路线。
- tunnel Map 的 `hostId + cliId` 结构。
- 第三阶段远端文件、Git、终端能力。

## 七、异常与安全

界面至少区分：Node.js 版本不足、Claude Code 不存在、SDK 加载失败、账号未登录、适配器上传或校验失败、服务启动失败、query 失败、会话不存在、取消或审批路由失效。

远端服务不得监听公网地址。日志不得包含登录凭据、完整敏感环境变量、审批密钥或未脱敏认证信息。

## 八、测试重点

- 适配器健康、会话扫描与正式 query 共存。
- 新会话、恢复、连续多轮、流式事件、取消和审批。
- 同一主机两个项目共用 Claude 服务但 cwd、session 和 query 不串线。
- 适配器首次安装、相同版本复用、内容不完整时重新安装。
- Node.js 不兼容、Claude 缺失、未登录、服务中断。
- 本机 Claude、远端 Codex 和远端 OpenCode 回归。

## 九、验收标准

1. SSH 项目中的 Claude 消息由绑定机器上的 Claude Code 执行。
2. 新建和恢复 query 均携带当前项目 cwd。
3. 已同步 Claude 会话可以继续对话，远端缺失时不在本机恢复。
4. 流式消息、取消和审批只作用于原 thread/query。
5. 同一主机多个项目共用一个 Claude 服务，但不会串 cwd 或 session。
6. 远端适配器只监听回环地址，版本安装和复用可验证。
7. 远端运行失败不会调用本机 Claude Code，本地项目行为不变。

## 十、阶段输出与下一阶段入口

本阶段输出三种目标 CLI 的 SSH 远端文本对话闭环。计划 4 在这三条稳定消息链路前增加统一附件上传步骤，不得让任何 CLI 直接接收本机文件路径。
