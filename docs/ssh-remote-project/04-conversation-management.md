# 第四阶段：对话管理设计

## 一、阶段目标

让远端项目的所有对话请求通过该项目绑定机器上的 CLI 执行。对话输入框底部的模型、思考强度和权限，以及健康状态、登录账号、用量、MCP、Skills 和其他 CLI 能力，都必须读取当前项目所在机器的运行时。

本阶段统一使用 SSH 隧道连接远端 CLI 服务，不部署常驻 Panes 服务端，不让远端 CLI 对外网监听，也不在远端失败时调用本机 CLI。

## 二、业务范围

本阶段包含：

- 本地项目和远端项目的对话执行目标自动切换。
- 远端 CLI 安装、版本、健康、账号、用量和能力检测。
- 模型、思考强度、权限等输入框选项按目标机器绑定。
- 新对话、继续对话、流式消息、取消、审批和恢复。
- Codex、OpenCode、Claude Code 现有对话协议的远端运行。
- 本地附件上传到远端缓存后再发送。
- CLI 运行时、模型缓存、会话和隧道按机器隔离。
- 手机远程访问触发消息时复用同一目标解析和发送入口。

本阶段不包含：

- 智能体运行工具整页按机器分组；总计划第五阶段当前已暂缓，不作为当前执行项。
- 定时任务暂停与恢复；总计划第六阶段当前已暂缓，不作为当前执行项。
- 为用户提供隧道端口配置或手动启动服务的界面。

## 三、概要设计

### 3.1 对话目标由项目决定

对话请求只提交线程 ID 和业务参数：

```text
thread_id
   │
   ▼
thread.workspace_id
   │
   ▼
ExecutionTargetResolver
   ├── Local → 本机 CLI 运行时
   └── Ssh   → 远端 CLI 运行时 + SSH 隧道
```

前端不能提交一个独立连接 ID 覆盖线程所属项目。线程创建后即归属于项目，切换界面当前项目不会改变旧线程的执行目标。

### 3.2 运行时注册表

现有只按 engine ID 管理的全局运行时需要改为按执行目标隔离：

```text
EngineRuntimeRegistry
├── local
├── ssh:<connection-id-1>
└── ssh:<connection-id-2>
```

机器能力缓存键：

```text
(ExecutionTarget, engine_id)
```

对话运行时键：

```text
(ExecutionTarget, engine_id, runtime_scope)
```

`runtime_scope` 由 CLI 启动描述确定：能承载多个目录的服务使用 machine；启动时绑定项目目录的服务使用 workspace ID。这只描述运行时生命周期，不改变统一 SSH 隧道方式。

### 3.3 通信结构

```text
Panes 对话客户端
      │
      ▼
本机 127.0.0.1:<local-port>
      │
      ▼
SSH 本地端口转发
      │
      ▼
远端 127.0.0.1:<remote-port>
      │
      ▼
远端 CLI 服务或协议适配器
```

所有服务只绑定远端回环地址。SSH 网关统一负责端口分配、远端进程、转发进程、就绪检查、存活检测和清理；各 CLI 适配器只描述如何启动和如何使用现有业务协议。

## 四、输入框详细设计

### 4.1 切换项目

用户切换项目时：

1. 前端获得当前 workspace ID。
2. 查询该项目当前线程或创建新线程所选 engine。
3. 后端解析项目执行目标。
4. `engineStore` 使用 `(target, engine)` 查询健康和能力。
5. 输入框更新模型、思考强度和权限选项。
6. 用量和账号等相关入口切换到同一目标缓存。

旧项目尚未完成的消息可以继续流式处理，但事件必须携带 workspace ID 和 thread ID，只更新所属线程，不能覆盖当前项目输入框状态。

### 4.2 模型选择

模型列表来自目标机器上的对应 CLI：

- 本地项目读取本机 CLI。
- 远端项目读取该 SSH 连接机器上的 CLI。
- 不把本机模型列表复制给远端项目。
- 远端 CLI 未安装或版本不兼容时，模型选择器显示不可用原因。

线程保存模型 ID，但每次发送前必须用线程所属目标的当前模型目录校验。模型在目标机器上已不可用时阻止发送，并提示重新选择；不能静默换成本机同名模型。

### 4.3 思考强度

思考强度选项由当前目标机器、当前 engine 和当前模型共同决定。切换模型后重新计算可选值；旧值不支持时选择该模型在目标机器上的默认值并向用户展示变化。

### 4.4 权限

权限选择沿用现有各 engine 的能力和映射，但读取、校验和审批都绑定线程目标：

- 当前目标不支持某权限模式时不展示。
- 审批请求事件携带 workspace/thread/target 身份。
- 用户同意或拒绝后，响应发回原远端运行时。
- 切换到其他项目不会把审批回复发到当前项目的运行时。

### 4.5 健康、账号与用量

健康状态、登录账号、用量、MCP、Skills 和扩展能力都按 `(ExecutionTarget, engine_id)` 缓存。页面展示连接名称，明确数据来自哪台机器。

缓存只做性能优化。发送消息和执行敏感操作时仍校验目标连接状态与运行时存活状态。

## 五、发送消息详细流程

### 5.1 新消息

1. 用户在某项目线程输入消息并点击发送。
2. 前端提交 thread ID、文本、附件引用、模型、思考强度和权限业务值。
3. 后端从线程查 workspace ID，再解析 ExecutionTarget。
4. 校验连接未删除、已启用且可达。
5. 校验所选 engine、模型和权限来自同一目标机器。
6. 如有附件，先完成远端上传。
7. 获取或创建目标隔离的 CLI 运行时。
8. 等待远端 CLI 服务和 SSH 隧道就绪。
9. 通过现有 engine 协议发送请求。
10. 按现有消息 DTO 和事件协议写入、推送流式内容。
11. 完成后保存 engine thread ID、用量和最终状态。

任一步失败都将当前发送标记为明确错误。未确认远端 CLI 和隧道就绪前，不能把“SSH 已连接”当成对话已可用。

### 5.2 继续和恢复对话

线程的 `engine_thread_id` 仍是对应 CLI 的会话 ID，并隐式属于线程的执行目标。恢复时必须：

- 在原项目目标上启动相同 engine。
- 使用原 engine thread ID 恢复。
- 校验运行时返回的会话属于目标机器。
- 远端缺失会话时提示会话无法恢复，不尝试在本机按相同 ID 恢复。

SSH 连接删除再恢复后，workspace、thread、message 和 engine thread ID 均不改变；只重新建立新的 SSH 隧道和 CLI 进程。

### 5.3 流式事件

所有远端事件标准化为现有聊天事件，并必须包含：

```text
workspace_id
thread_id
engine_id
runtime_key
event sequence
```

前端按 thread ID 更新消息。事件断线后先关闭对应订阅和运行时状态，再把线程标记中断或错误，不能把另一台机器的事件接到该线程。

### 5.4 取消和审批

取消请求根据 thread ID 找到原 runtime key，发给原远端 CLI。找不到运行时时仍更新本地可恢复状态，但不能向当前活动项目运行时广播取消。

审批请求在数据库和内存中保存与线程、消息及 runtime key 的关联。回复审批前重新校验关联，防止多机器、多个线程并行时串线。

## 六、附件详细设计

远端项目不能把本机附件路径直接交给远端 CLI。

### 6.1 上传流程

1. 前端沿用现有附件选择和预览。
2. 发送前后端验证本机附件存在、大小和类型符合现有约束。
3. 在远端创建按 workspace/thread 隔离的缓存目录。
4. 通过 SSH 标准输入上传，文件名使用生成的安全名称，原文件名只作为元数据。
5. 校验上传字节数或摘要。
6. 把远端缓存路径传给远端 CLI。
7. 全部附件成功后才启动消息请求。

远端缓存示例：

```text
~/.cache/panes/attachments/<workspace_id>/<thread_id>/
```

### 6.2 失败与清理

- 任一附件失败，整次消息发送失败。
- 不把本机路径继续传给远端 CLI。
- 不改用本机 CLI。
- 会话结束、用户删除附件缓存或缓存过期时，通过原 SSH 连接清理。
- 连接不可达时记录待清理项，下一次连接成功后清理；不能阻塞用户查看历史消息。

## 七、各对话 CLI 的远端启动设计

### 7.1 Codex

远端按需启动当前 Codex app-server 的 WebSocket 监听，绑定远端 `127.0.0.1`。本地通过 SSH 转发后的 WebSocket 地址继续使用现有 app-server 协议。

模型、账号、用量、权限、会话恢复和消息事件均从这条目标隔离连接获取。远端版本不支持所需 WebSocket 能力时，健康检查显示版本不兼容；首版不切换为另一套专用 SSH stdio 通信。

### 7.2 OpenCode

远端按需启动 OpenCode 服务，绑定远端 `127.0.0.1`。本地 HTTP/SSE 客户端连接 SSH 转发后的本机端口。

运行时认证密钥在每次启动时生成，只存在于进程环境和本地运行时内存中，不写数据库、不写日志。远端服务退出或认证失败时关闭隧道并使该目标运行时失效。

### 7.3 Claude Code

Claude 对话继续使用 Panes 当前协议适配器，用户不需要配置额外服务。

首次使用某应用版本时：

1. 计算适配器和依赖内容版本。
2. 通过统一 SSH 数据通道上传到远端版本目录。
3. 校验完整性，版本相同则复用，不覆盖正在运行的旧版本。
4. 在远端启动适配器，由它调用远端 Claude Code 并读取远端账号环境。
5. 适配器只监听远端回环端口。
6. 本地客户端通过 SSH 隧道继续使用现有 JSON 行协议。

远端缺少 Claude Code 或适配器所需运行环境时，健康状态显示不可用，不调用本机 Claude Code 替代。适配器按需启动并随运行时关闭，不是常驻 Panes 服务端。

### 7.4 统一约束

上述差异只存在于 CLI 启动描述和原有业务协议中。以下能力统一由 SSH 网关处理：

- SSH 认证。
- 远端和本地端口分配。
- 端口转发。
- 进程存活和就绪检测。
- 超时、取消和清理。
- 连接禁用、删除及应用退出处理。

不能为某个 CLI 绕开 SSH 网关直接暴露 HTTP 接口或开放远端公网端口。

## 八、运行时就绪与生命周期

### 8.1 就绪条件

运行时可用必须同时满足：

1. SSH 认证成功。
2. 远端 CLI 或适配器进程仍存活。
3. 远端回环端口已监听。
4. 本地端口转发进程仍存活。
5. 本机转发端口能完成对应协议健康握手。

任何一步失败都返回对应阶段错误，不能只根据 SSH 进程存在就标记健康。

### 8.2 清理条件

以下事件关闭目标相关运行时、隧道、事件订阅和待处理请求：

- SSH 连接禁用。
- SSH 连接删除。
- 隧道或远端进程异常退出。
- 应用退出。
- 运行时空闲超过内部生命周期。

连接恢复或重新启用后按需创建新运行时，不复用旧端口或旧进程句柄。

## 九、手机远程访问消息

手机端触发消息继续进入现有统一消息发送入口：

1. 根据手机请求中的线程 ID 查询线程。
2. 从线程查询 workspace ID。
3. 从项目解析本地或 SSH 目标。
4. 使用与桌面输入框相同的目标隔离运行时发送。

手机请求不能额外指定 connection ID，也不能因为请求来自远程设备就固定调用本机 CLI。

## 十、前端状态设计

### 10.1 Engine 状态

`engineStore` 从按 engine ID 的全局状态调整为按 target key 和 engine ID：

```text
enginesByTarget
healthByTargetAndEngine
modelsByTargetAndEngine
usageByTargetAndEngine
accountByTargetAndEngine
capabilitiesByTargetAndEngine
```

target key 由后端返回稳定表示，前端不自行用显示名称拼接。

### 10.2 Chat 状态

`chatStore` 的流式状态、待审批状态、运行时引用和用量更新按 thread ID 保存。当前活动线程只是视图选择，不能作为事件归属依据。

切换目标时保留各目标缓存，避免反复扫描；连接状态变化或用户刷新时使对应目标缓存失效。

## 十一、后端接口设计

现有对话接口保持以 thread ID 为核心，目标在后端解析。需要调整的接口族：

| 接口族 | 设计 |
| --- | --- |
| engine 列表与健康 | 增加 workspace/thread 上下文，返回目标隔离能力 |
| 模型与用量 | 按目标机器查询和缓存 |
| 发送消息 | thread ID 解析目标，禁止 connection ID 覆盖 |
| 取消与审批 | thread/runtime 关联路由 |
| 会话同步与恢复 | 在原目标 engine 上执行 |
| 附件 | 远端项目前置上传并返回远端路径 |
| 运行时事件 | 携带 workspace/thread/runtime 身份 |

后端主要新增或调整：

- `EngineRuntimeRegistry`
- target-aware engine runtime key
- 各 engine 的远端启动描述
- 隧道就绪检查
- 远端适配器版本管理
- 统一附件上传和清理

## 十三、错误处理

### 13.1 一轮对话统一异常模板

`run_turn(...)` 是普通聊天一轮对话的唯一顶层执行模板。Codex、OpenCode、Claude Code 的发送任务、事件接收任务、用户取消和事件空闲超时都由这一层统一等待。

统一流程如下：

```text
启动当前 CLI 的发送任务
→ 同时等待发送结果、EngineEvent、用户取消和超时
→ 正常事件继续处理
→ 任一不可恢复错误进入本轮唯一异常出口
→ 记录日志
→ 调用当前 CLI 的 interrupt(...)
→ 停止本轮其他任务
→ 通知前端
→ 标记本轮失败
→ 清理并持久化本轮状态
```

`CliTool::send_message(...)` 及其底层监听任务只负责上报结果：

- 正常过程上报 `EngineEvent`。
- 无法继续时返回 `Err`，或上报 `recoverable: false` 的 `EngineEvent::Error`。
- 发送实现和监听任务不得自行完成日志、前端提示和异常收尾。
- 监听任务不得只记录致命错误后继续等待，连接关闭、事件读取失败、事件解析失败和事件丢失必须上报当前轮。

每轮使用独立的 `event_rx`，异常只允许影响当前轮。`run_turn(...)` 只处理收到的第一条致命错误，防止并发错误导致重复提示和重复取消。

统一模板不得判断当前是哪一种 CLI，不得匹配 `websearch`、具体接口或具体错误文本。各 CLI 只实现自己的发送、事件转换和取消协议。

界面至少区分：

- SSH 连接已删除或禁用。
- SSH 不可达或隧道中断。
- 远端 CLI 未安装。
- 远端 CLI 版本不兼容。
- 远端适配器上传、校验或启动失败。
- 模型在目标机器上不可用。
- 权限模式不受目标 CLI 支持。
- 账号未登录或用量查询失败。
- 附件上传失败。
- 远端会话不存在或恢复失败。

错误提示应带连接显示名称和 engine 名称，但日志不得包含私钥内容、运行时密钥或用户消息之外的敏感环境变量。

## 十四、测试设计

### 14.1 目标隔离测试

- 本地、远端 1、远端 2 的 engine 健康、模型、账号和用量互不覆盖。
- 两台机器同 engine、同模型 ID 仍使用各自运行时。
- 切换项目时输入框选项随目标切换。
- 后台线程事件只更新原线程。

### 14.2 对话流程测试

- 三个当前对话 engine 的新会话、继续会话、流式消息和取消。
- 审批请求与回复准确路由。
- 应用重启后远端会话恢复。
- 连接中断、远端进程退出和隧道退出。
- 删除并恢复连接后仍使用原线程和 engine thread ID。

### 14.3 附件测试

- 单个和多个附件上传。
- 空格、中文和特殊字符文件名。
- 上传失败、校验失败和发送前断线。
- 远端缓存清理。
- 远端 CLI 永远收不到本机路径。

### 14.4 安全测试

- 远端服务只监听回环地址。
- 本机转发端口只供当前 Panes 运行时使用。
- 临时认证密钥不写数据库和日志。
- 前端伪造 connection ID 无法改变线程目标。
- 任一远端失败不触发本机 CLI。

### 14.5 本地回归

- 本地项目的模型、权限、发送、审批、取消和会话恢复不变。
- 现有手机远程访问发送本地项目消息不变。

## 十五、阶段验收标准

1. 远端项目输入框的模型、思考强度和权限来自该远端机器。
2. 健康状态、登录账号、用量、MCP、Skills 和扩展能力按机器隔离。
3. Codex、OpenCode 和 Claude Code 的消息都由远端对应 CLI 执行。
4. 所有需要端口的远端 CLI 只监听远端回环地址，并通过 SSH 隧道连接。
5. 新对话、恢复、流式事件、取消和审批均能正确工作。
6. 本地附件先上传远端，成功后才发送；失败时整次发送失败。
7. 切换项目不会串模型、串运行时、串事件或串审批。
8. 连接禁用、删除、不可达或 CLI 不兼容时有明确错误。
9. 任意失败都不会调用本机 CLI 作为后备。
10. 本地项目和手机远程访问原有对话行为没有回归。

## 十六、阶段输出与下一阶段入口

本阶段输出按机器隔离的 CLI 能力和统一远端消息发送入口。第四阶段剩余工作在计划 5 完成后收口；第4阶段剩余工作计划 6 已取消。总计划第五阶段和第六阶段当前均已暂缓，不作为当前执行项。
