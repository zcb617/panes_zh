## 一、文档定位

本文是第四阶段剩余工作的第 6 个实施计划，也是第四阶段收口计划。它不再新增单个 CLI 的基础对话能力，而是验证并补齐本地与多台 SSH 远端机器并行运行时的事件归属、异常恢复、连接清理和手机统一发送入口。

## 二、阶段目标

本阶段结束后，本地项目、远端机器 A 和远端机器 B 可以同时进行对话。切换项目、SSH 断线、连接禁用或删除、远端服务退出以及手机发送消息时，模型、消息、取消和审批均不会串线，也不会回退到错误机器。

## 三、业务范围

本阶段包含：

- 本地和多台 SSH 机器上的多线程并行对话。
- 流式事件、用量、状态和通知按 workspace/thread/target 精确归属。
- 取消和审批回复路由到原运行时。
- SSH 禁用、删除、断线和远端 CLI 退出时的清理。
- 连接恢复后继续使用原 workspace、thread 和 engine thread ID。
- 手机消息根据 thread 解析执行目标并复用桌面发送入口。
- 应用退出时终止活动请求、远端 CLI 服务和 tunnel 相关资源。
- 三种远端 CLI、本地路线、附件和运行时信息的综合回归。

本阶段不包含：

- 第五阶段智能体运行工具整页分组；总计划第五阶段当前已暂缓。
- 第六阶段定时任务暂停与恢复；总计划第六阶段当前已暂缓。
- 手机端额外指定 SSH connection ID。
- 本地或远端失败后的跨机器自动降级。

## 四、并行归属结构

每个运行中 turn 至少具备以下稳定身份：

```text
workspace_id
thread_id
engine_id
target_key
runtime_key
event_sequence
```

前端按 thread ID 更新消息，并使用 workspace/target 校验事件。当前活动 workspace 只决定界面显示，不能决定事件写入对象。

## 五、主要工作

### 5.1 多目标并行

- 本地项目、远端 A、远端 B 可以并行运行相同 engine。
- 同一远端主机不同项目可以共用 CLI 服务，但各自拥有独立 thread、cwd 和 turn 状态。
- 后台 thread 的流式事件继续更新原 thread；切换页面不取消原 turn。
- 事件序号用于识别重复、迟到或断线后的无效事件。

### 5.2 取消与审批收口

- 取消只根据 thread 的运行时关联发送，不向当前活动 runtime 广播。
- 审批请求持久化 engine、thread 和原远端路由信息。
- 用户切换项目后回复旧审批，仍必须回到原机器、原 CLI、原请求。
- 原运行时已失效时，审批回复显示明确失败并更新本地可恢复状态。

### 5.3 连接禁用、删除和断线

- SSH 连接禁用或删除时，取消该目标的活动 turn，关闭事件订阅并释放持续占用。
- 清理对应远端 CLI 服务和 tunnel，不影响其他连接和本地运行时。
- SSH 瞬时断线或远端服务退出时，把受影响 thread 标记为中断或错误。
- 不清除 workspace、thread、message 或 engine thread ID。

### 5.4 恢复

- 连接恢复或重新启用后，重新建立 tunnel 和按需 CLI 服务。
- 用户再次发送时在原目标上恢复原 engine thread ID。
- 远端会话确实不存在时提示无法恢复，不创建本机同 ID 会话。
- 恢复不能复用旧端口、旧进程句柄或失效订阅。

### 5.5 手机统一入口

```text
手机请求中的 threadId
  -> 查询 thread.workspaceId
  -> 后端解析 ExecutionTarget
  -> 复用桌面 send_message_inner
```

- 手机请求不能提交 connection ID 覆盖目标。
- 本地 thread 继续使用本机 CLI，SSH thread 使用绑定机器上的 CLI。
- 附件若来自现有手机上传流程，必须进入计划 4 的远端附件转换步骤。
- 手机取消或后续审批同样按 thread/runtime 路由。

### 5.6 应用退出

- 停止接受新 turn。
- 取消活动请求并关闭事件订阅。
- 释放或清空持续占用。
- Registry 关闭远端 CLI 服务，再按既有规则销毁 tunnel。
- 不修改业务会话和消息数据。

## 七、异常、安全与数据保持

界面至少区分：连接禁用、连接删除、SSH 断线、远端服务退出、运行时已失效、审批已过期、远端会话不存在。

任何异常均应保留 workspace、thread、message 和 engine thread ID。只有活动运行状态和连接资源可以被清理。前端或手机伪造 connection ID 不得改变目标。

## 八、测试矩阵

### 8.1 多目标

- 本地 Codex + 远端 A Codex + 远端 B Codex 并行。
- 同一远端主机两个项目并行使用同一 CLI。
- Codex、OpenCode、Claude 在同一或不同机器并行。

### 8.2 事件与操作

- 切换项目期间持续收到后台流式事件。
- 两条 thread 同时出现审批并分别回复。
- 取消其中一条 thread，不影响其他 thread。
- 迟到事件、重复事件和运行时失效后的事件不污染界面。

### 8.3 故障与恢复

- SSH 断线、连接禁用、连接软删除、远端 CLI 被终止。
- 恢复连接后继续原会话。
- 远端会话删除后的明确失败。
- 应用退出和重新启动后的状态恢复。

### 8.4 手机与回归

- 手机发送本地 thread 和三种 SSH thread。
- 手机请求无法覆盖 connection ID。
- 手机附件进入远端上传流程。
- 本地对话、会话刷新、第三阶段工作区能力全部回归。

## 九、验收标准

1. 本地、远端 A、远端 B 可以同时对话，消息和状态互不覆盖。
2. 切换项目不会改变后台 thread 的事件归属。
3. 取消和审批始终到达原机器、原 CLI 和原 thread。
4. 连接禁用、删除、断线或服务退出只影响对应目标。
5. 连接恢复后可以使用原 thread 和 engine thread ID 继续远端会话。
6. 手机消息只根据 thread 解析目标，不能指定其他连接。
7. 任意远端失败都不会调用本机或其他远端机器作为后备。
8. 应用退出后没有遗留活动请求或远端 CLI 服务，业务数据保持完整。
9. 本地项目及第三阶段 SSH 工作区能力没有回归。
