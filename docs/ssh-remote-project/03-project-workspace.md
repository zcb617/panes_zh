# 第三阶段：项目工作区设计

## 一、阶段目标

让第二阶段创建的远端项目具备完整工作区能力。用户进入远端项目后，文件浏览与编辑、Git、工作树、终端和项目启动配置均在该项目绑定的远端 Linux 电脑上执行，界面与现有本地项目保持一致。

本阶段的核心不是新建一套远端页面，而是让现有项目工作区根据 `workspace_id` 自动选择本地或 SSH 执行目标。

## 二、业务范围

本阶段包含：

- 远端目录树加载、搜索和刷新。
- 远端文件读取、保存、新建、重命名及现有文件操作。
- 远端 Git 仓库发现、状态、diff、日志、分支、提交、拉取和推送。
- 远端 Git 工作树查询、创建和现有工作树操作。
- 远端交互终端的创建、输入、输出、调整尺寸、中断和关闭。
- 工作区启动配置在远端终端中执行。
- 远端项目连接状态和操作错误在现有工作区中展示。
- 文件和 Git 的远端刷新机制。

本阶段不包含：

- 对话消息、模型、权限和 CLI 隧道，它们在第四阶段实现。
- 智能体运行工具页的机器分组；总计划第五阶段当前已暂缓，不作为当前执行项。
- 远端桌面、端口管理器或通用文件传输界面。

## 三、概要设计

### 3.1 界面保持一致

远端项目继续使用现有主界面：

- 左侧项目和对话列表。
- 中间对话或编辑器区域。
- 文件资源管理器。
- Git 面板。
- 底部终端。
- 项目设置中的仓库和启动配置。

不为远端项目复制一套页面。界面只增加以下目标提示：

- 项目名称旁显示远端标识和连接显示名称。
- 文件、Git、终端区域在连接禁用、删除或不可达时显示对应状态。
- 长时间远端操作显示正在连接或正在执行，不让用户误认为界面无响应。

### 3.2 后端执行入口

所有工作区操作从 `workspace_id` 解析目标：

```text
工作区操作(workspace_id, 业务参数)
             │
             ▼
ExecutionTargetResolver
       ├── Local → 现有本地实现
       └── Ssh   → SshRuntimeGateway
                        ├── exec
                        ├── upload / download
                        └── pty
```

前端传入的文件路径、仓库路径或终端工作目录只能是项目目标内部的业务参数，不能决定命令在本机还是远端执行。

### 3.3 适配方式

现有文件、Git、工作树和终端命令保留业务含义，在后端命令入口增加目标分派：

- Local 分支复用现有实现。
- Ssh 分支调用对应远端实现。
- 两个分支返回相同 DTO 和事件格式，前端不按协议维护两套状态。

公共目标分派可以按业务模块实现稳定接口，但不能把只有一个调用点的逻辑为了“看起来通用”而额外拆函数。

## 四、远端路径设计

### 4.1 路径身份

远端项目的 `root_path` 是创建时经过远端 `realpath` 解析的 Linux 绝对目录。工作区内部优先使用：

```text
workspace_id + relative_path
```

后端按项目根目录解析实际路径，不能接受前端传入任意绝对路径绕过项目边界。

### 4.2 路径校验

每次文件或仓库操作都必须：

1. 根据 `workspace_id` 加载项目和连接。
2. 验证连接未删除且已启用。
3. 使用 POSIX 路径规则拼接项目根目录和相对路径。
4. 在远端解析目标或父目录的实际路径。
5. 确认实际路径位于项目根目录或该项目已经登记的工作树根目录内。
6. 再执行读取、写入或 Git 操作。

拒绝 `..` 越界、符号链接逃逸、空字节和不合法路径。Windows 的反斜杠、小写归一化和盘符规则不能用于远端路径。

### 4.3 命令参数

远端命令参数必须使用安全参数通道或集中、经过测试的 POSIX 引号规则。不能把前端路径直接拼接进 shell 字符串。文件名包含空格、单引号、换行、中文或以连字符开头时都必须正确处理。

## 五、文件工作区详细设计

### 5.1 打开远端项目

1. 用户在侧栏选择远端项目。
2. `workspaceStore` 激活该项目。
3. 文件仓库清除上一个项目的可见目录缓存，但可以保留按 workspace ID 隔离的后台缓存。
4. 前端调用现有工作区目录接口并传入 `workspace_id`。
5. 后端解析为 SSH 目标，读取项目根目录第一页。
6. 返回与本地一致的 `FileTreeEntry` 和分页信息。
7. 文件资源管理器显示远端内容。

若连接不可用，文件树显示目标错误和“重试”，不能显示本机同名路径内容。

### 5.2 目录树与搜索

远端目录读取需要支持现有的：

- 懒加载子目录。
- 分页。
- 刷新。
- 文件名搜索。
- 忽略规则和可见性约定。
- Git 仓库标识所需的目录信息。

搜索在远端项目范围内执行。结果返回项目相对路径和必要元数据，不能把远端绝对路径当成本机可打开路径。

### 5.3 打开文件

1. 前端提交 `workspace_id` 和相对路径。
2. 后端完成边界校验。
3. 通过 SSH 数据通道读取文件字节和元数据。
4. 继续使用现有编码识别、二进制判断、体积限制和只读提示。
5. 返回内容时附带修改时间或内容版本，用于保存冲突检测。

文件读取失败要区分：不存在、无权限、目录、超限、二进制、连接中断和编码错误。

### 5.4 保存文件

远端保存沿用现有编辑器保存入口：

1. 前端提交 workspace ID、相对路径、内容和打开时版本。
2. 后端重新检查文件是否已被外部修改。
3. 在目标文件同目录创建临时文件。
4. 通过 SSH 标准输入写入临时文件。
5. 尽可能保留原文件权限。
6. 在远端原子替换目标文件。
7. 返回新的修改时间或内容版本。
8. 前端清除脏状态并刷新 Git 状态。

上传或替换失败时保留编辑器未保存内容，不能把内容保存到本机临时同名路径冒充成功。

### 5.5 其他文件操作

现有新建文件、创建目录、重命名、移动及删除等入口按相同原则路由到远端。每项操作必须先校验目标范围，成功后只刷新受影响的目录和 Git 状态。

危险操作继续使用现有确认交互；连接中断时不得根据界面乐观状态判定成功，必须以远端命令结果为准。

### 5.6 文件变化刷新

本地文件监听器不能监听远端目录。远端项目采用受控轮询：

- 文件资源管理器可见时，按已展开目录查询轻量目录指纹。
- 编辑器中打开的文件按修改时间或版本检测外部变化。
- 页面不可见、项目非当前项目或连接不可用时停止轮询。
- 用户操作成功后立即刷新相关节点，不等待下一轮。
- 多个面板对同一 workspace 的刷新合并，避免产生并发 SSH 风暴。

轮询间隔作为内部配置集中管理，不在首版设置页增加用户配置。

## 六、Git 与工作树详细设计

### 6.1 仓库发现

现有仓库扫描命令增加 workspace ID 目标解析。远端项目通过 SSH 在项目范围内发现 Git 仓库，返回与本地一致的 Repo DTO。

仓库实际路径保存在项目目标内。前端提交的 `repo_id` 或仓库相对路径不能把命令切到本机。

### 6.2 Git 操作

远端 Git 统一在远端执行，逻辑等价于：

```text
git -C <remote-repo-path> <subcommand> <arguments>
```

覆盖当前 Panes 已有功能：

- 状态与暂存区。
- diff 和文件内容。
- 提交历史。
- 分支查询、创建、切换和删除。
- stage、unstage、discard、commit。
- fetch、pull、push。
- 仓库设置相关的现有命令。

Git 参数继续使用现有业务校验，凭据交互行为由远端 Git/SSH 环境决定。需要用户交互但当前协议不支持时返回明确错误，不转交本机 Git。

### 6.3 Git 状态刷新

- Git 操作完成后立即刷新当前仓库。
- Git 面板可见时进行短周期状态轮询。
- 面板不可见、应用后台或项目非当前项目时停止。
- 同一仓库同一类型刷新去重。
- 网络慢时不并发堆积下一轮请求。

### 6.4 工作树

远端工作树的查询、创建、打开、重命名和现有操作都在远端执行。工作树路径必须：

- 属于当前项目登记的仓库。
- 经远端 `realpath` 解析。
- 作为该 workspace 的允许根目录登记。

打开远端工作树后，文件、Git 和终端仍使用原 workspace 的 SSH 连接，不创建新的 SSH 连接记录。

## 七、远端终端详细设计

### 7.1 创建终端

用户在远端项目打开终端时：

1. 前端调用现有创建终端接口并传 `workspace_id`。
2. 后端解析到 SSH 连接和项目根目录。
3. 创建本地受控 PTY。
4. PTY 中启动系统 SSH 并请求远端 TTY。
5. 远端进入项目根目录或当前工作树目录。
6. 启动远端登录 shell。
7. 终端 ID 仍按 workspace ID 隔离并返回前端。

用户看到的是现有终端面板，不需要理解本地 PTY 和远端 TTY 的两层结构。

### 7.2 终端交互

现有协议继续处理：

- 输入字节。
- 输出事件。
- 行列尺寸调整。
- Ctrl+C 等中断。
- 多终端标签。
- 终端关闭与重连。

终端标题增加远端连接名称。SSH 退出码和错误写入终端输出，同时向状态仓库发送结构化关闭原因。

### 7.3 终端生命周期

连接禁用、删除或应用退出时关闭其全部远端终端。临时网络中断导致 SSH 进程退出时，该终端标记已断开，用户点击“重新连接”创建新会话；不自动在本机项目目录创建终端。

## 八、项目启动配置

项目设置中的启动配置保持现有编辑方式。应用启动配置时：

- 相对工作目录以远端项目或远端工作树为基准解析。
- 每个终端会话通过远端 PTY 创建。
- 启动命令在远端 shell 中执行。
- 分屏、活动终端和默认工作区视图仍由前端布局管理。
- 连接不可用时整个启动过程失败并显示具体会话，已经成功创建的远端会话按现有回滚或保留约定处理，不能创建本地替代会话。

## 九、后端接口设计

现有接口优先增加或统一 `workspace_id`，避免新增一套带 `remote_` 前缀的平行业务 API。

主要接口族：

| 接口族 | 目标分派 |
| --- | --- |
| 文件树、搜索、读取、写入、文件操作 | workspace ID → Local/Ssh |
| 仓库扫描、Git 状态和 Git 操作 | workspace ID/repo ID → Local/Ssh |
| 工作树操作 | workspace ID/repo ID → Local/Ssh |
| 终端创建 | workspace ID → Local PTY/SSH PTY |
| 终端输入、尺寸和关闭 | terminal session ID → 已登记目标 |
| 启动配置应用 | workspace ID → 对应终端目标 |

终端 session、文件请求和 Git 请求在创建时登记 workspace ID 与执行目标。后续事件必须携带 workspace ID，防止切换项目后旧响应污染当前界面。

## 十、前端状态设计

现有仓库按 workspace ID 继续隔离：

- `workspaceStore`：项目目标展示和激活。
- `fileStore`：目录缓存、打开文件和远端刷新状态。
- `gitStore`：仓库和请求按 workspace/repo 隔离。
- `terminalStore`：终端 session 按 workspace 隔离。
- `uiStore`：当前工作区表面和面板可见性。

增加统一的目标可用性展示状态，但不把连接参数复制到各仓库。各仓库只保存 workspace ID 和请求状态，真正目标仍由后端解析。

## 十二、测试设计

### 12.1 路径安全测试

- 普通相对路径、空格、中文、引号、换行和连字符文件名。
- `..` 越界、绝对路径注入和符号链接逃逸。
- Linux 大小写敏感路径。
- 项目根目录和登记工作树根目录边界。

### 12.2 文件测试

- 大小目录分页、展开、搜索和刷新。
- 文本读取、保存、外部修改冲突和原子替换。
- 无权限、文件消失、连接中断和上传失败。
- 远端刷新停止和恢复条件。
- 远端失败时本机同名路径不发生变化。

### 12.3 Git 测试

- 仓库发现、status、diff、日志、分支、提交、拉取和推送。
- 多仓库和多工作树。
- 操作后立即刷新及可见时轮询。
- 两台远端同路径仓库状态互不污染。

### 12.4 终端测试

- 创建、输入、输出、尺寸、中断和关闭。
- 默认进入项目或工作树目录。
- 多个远端终端并行。
- 禁用、删除和网络中断后正确关闭。
- 重连创建新 SSH 会话，不创建本地会话。

### 12.5 本地回归

- 本地文件监听器继续工作。
- 本地 Git、工作树和终端接口结果不变。
- 本地启动配置行为不变。

## 十三、阶段验收标准

1. 进入远端项目后，文件树展示远端目录而不是本机同名目录。
2. 远端文件可以打开、编辑、保存，并正确处理外部修改和错误。
3. 当前已有 Git 与工作树功能都能在远端仓库执行。
4. 远端 Git 状态能自动刷新，非当前页面不会持续无意义轮询。
5. 终端在远端项目目录启动，输入、输出、调整尺寸和中断正常。
6. 项目启动配置中的命令和工作目录都在远端执行。
7. 连接禁用、删除、不可达时各工作区入口明确失败。
8. 任何远端失败都不会调用本机文件、Git 或终端作为后备。
9. 两台远端电脑和本地项目的文件、Git、终端状态完全隔离。
10. 原有本地工作区全部功能没有回归。

## 十四、阶段输出与下一阶段入口

本阶段输出可用的远端项目工作区、SSH 数据通道和 SSH PTY。第四阶段在相同项目目标解析基础上增加 CLI 隧道和远端对话，不改变项目绑定关系。
