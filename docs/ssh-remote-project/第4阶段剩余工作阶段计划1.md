# 第4阶段剩余工作阶段计划1：SSH 远端 Codex 对话闭环

## 一、文档定位

本文是第四阶段剩余工作的第 1 个实施计划，目标是先交付 SSH 远端项目的 Codex 完整文本对话能力，并在这个真实业务中建立后续 CLI 共用的执行目标分流机制。

本计划以 [`00-general-rules.md`](00-general-rules.md) 为最高阶段约束，并承接 [`04-conversation-management.md`](04-conversation-management.md) 已确定的对话管理目标。

实施状态：开发和自动化验证已完成，等待用户使用 `src-tauri/target/release/Panes.exe` 完成本地功能验收。

## 二、阶段目标

本阶段结束后，用户可以在 SSH 远端项目中创建或打开 Codex 会话，通过项目绑定机器上的 Codex 继续发送文本消息，并正常接收流式回复、取消运行和处理审批。

本地项目仍使用本机 Codex，SSH 远端失败时必须明确报错，不得回退到本机 Codex。

## 三、业务范围

本阶段包含：

- 根据 `thread -> workspace -> sshConnectionId` 解析真实执行目标。
- 本地线程继续进入现有本机 `EngineManager`。
- SSH 线程通过 `hostId + codex` 取得共享 tunnel 和远端 Codex 服务入口。
- 同一远端主机只使用一个 Codex 服务入口，每次请求携带当前项目 `cwd`。
- 支持新会话、恢复已同步会话、发送文本消息和流式回复。
- 支持取消、审批回复和对话状态持久化。
- 对话执行期间登记并释放远端 Codex 持续服务占用。
- Codex 模型、思考强度、权限及发送前校验来自目标机器。
- 建立后续 OpenCode、Claude Code 可以复用的执行目标身份和路由契约。

本阶段不包含：

- OpenCode 和 Claude Code 正式对话。
- 本机附件上传及远端附件发送。
- MCP、Skills、账号、用量等全部运行时信息的统一展示。
- 手机入口和多机器综合验收。

## 四、业务与运行结构

```text
threadId
  -> 查询 thread.workspaceId
  -> 查询 workspace.locationKind
     -> local：现有本机 EngineManager
     -> ssh：workspace.sshConnectionId
             -> SshCliTunnelRegistry(hostId + codex)
             -> 机器级 Codex 服务入口
             -> 每次请求携带 workspace.rootPath 作为 cwd
```

远端 Codex 的 tunnel 和服务 key 只能是 `hostId + codex`。`workspaceId`、项目目录和 `threadId` 只能作为业务请求上下文或持续占用凭证，不能进入 tunnel key。

## 五、主要工作

### 5.1 执行目标解析

- 在后端从 thread 反查 workspace，形成稳定的本地或 SSH 执行目标。
- 前端不得提交 connection ID 覆盖线程归属。
- SSH 连接已删除、已禁用或未绑定时，发送前直接返回可识别错误。

### 5.2 远端 Codex 运行时

- 为远端 Codex 建立独立协议适配，不修改本机 Codex 的业务语义。
- 通过 tunnel 暴露的本机 WebSocket 地址连接远端 app-server。
- 远端运行时按 `hostId + codex` 隔离；不同主机不得共享协议状态、模型缓存、审批或活动 turn。
- 新建和恢复会话时始终传入当前远端项目 `cwd`。

### 5.3 正式对话流程

1. 用户在 SSH 项目的 Codex 线程发送文本消息。
2. 后端从 thread 解析远端目标并校验连接。
3. 申请该 `hostId + codex + threadId` 的持续服务占用。
4. 确保远端 Codex 服务、SSH tunnel 和协议握手可用。
5. 使用远端模型、权限及项目 `cwd` 新建或恢复 engine thread。
6. 发送消息并把远端事件映射为现有聊天事件。
7. 按 thread ID 写入消息、状态、用量和 engine thread ID。
8. turn 完成、取消或失败后释放本次持续占用；释放不能关闭仍被其他业务占用的服务。

### 5.4 取消与审批

- 取消请求必须从 thread 找到原远端 Codex 运行时。
- 审批请求保存 thread、workspace、engine 和远端运行时身份。
- 审批回复只能发送回产生该审批的远端运行时。
- 找不到原运行时时明确失败，不能广播到当前活动项目或本机 Codex。

### 5.5 最小输入框联动

- SSH Codex 线程显示远端 Codex 可用模型和对应思考强度。
- 权限选项使用远端 Codex 实际支持范围。
- 所选模型在远端不存在时阻止发送并提示重新选择。
- 本阶段只完成 Codex 闭环所需信息；三种 CLI 的统一状态展示在计划 5 完善。

## 六、状态与生命周期

- 会话历史存在不等于服务持续占用存在。
- 每次正式发送开始前申请持续占用，turn 完成、取消或失败后释放相同 thread 的占用。
- 后台会话同步的临时占用与正式对话的持续占用可以并存。
- SSH 断线或远端 Codex 退出时，当前 turn 标记为中断或错误，并清理对应订阅和占用。
- 连接恢复后，复用原 workspace、thread 和 engine thread ID，新建 tunnel/服务进程句柄。

## 七、计划修改范围

计划修改或新增：

- `src-tauri/src/commands/chat.rs`：在发送、取消、审批入口按 thread 解析目标并分流。
- `src-tauri/src/commands/engines.rs`：增加 Codex 所需的 workspace/thread 目标上下文。
- `src-tauri/src/engines/`：新增 SSH 远端 Codex 独立运行时或协议适配模块。
- `src-tauri/src/ssh/runtime.rs`：复用并完善 workspace 执行目标解析契约。
- `src-tauri/src/ssh/cli_tunnel_registry.rs`：仅在现有持续占用契约缺少必要行为时补充。
- `src-tauri/src/state.rs`：登记目标隔离的远端对话运行时状态。
- `src/lib/ipc.ts`、`src/stores/engineStore.ts`、`src/stores/chatStore.ts` 及 Codex 输入框相关组件：接入目标上下文和远端状态。
- 对应 Rust、TypeScript 和组件测试。

明确不修改：

- `list_codex_remote_threads`、`attach_codex_remote_thread` 等本机外部 CLI 服务路线。
- 本地 Codex 的目标解析和运行语义。
- 第三阶段的远端文件、Git、工作树和终端业务。
- tunnel Map 的 `hostId + cliId` 结构。

实际开发前仍须按代码现状再次缩小文件清单；不得把计划清单理解为无条件修改授权。

## 八、异常与安全

界面至少区分：SSH 连接不存在、连接禁用、SSH 不可达、远端 Codex 未安装、版本不兼容、服务启动失败、协议握手失败、模型不可用、会话不存在、审批路由失效。

日志不得记录 SSH 私钥、完整敏感环境变量或运行时凭证。任一远端错误都不得触发本机 Codex。

## 九、测试重点

- 本地 Codex 与远端 Codex 分流测试。
- 远端新会话、已同步会话恢复、连续多轮消息。
- 流式文本、thinking、工具事件及最终状态映射。
- 取消和审批精确路由。
- 同一主机两个项目共用服务但 `cwd` 和 thread 不串线。
- 远端断线、服务退出和会话不存在。
- 本地 Codex 发送、恢复、取消和审批回归。

## 十、验收标准

1. 在 `llm_router` 等 SSH 项目中打开已同步 Codex 会话后，可以继续收到远端 Codex 回复。
2. 新建 Codex 会话时，会话实际创建在项目绑定的远端机器和项目目录中。
3. 模型、思考强度和权限来自远端 Codex；远端不存在的模型不能发送。
4. 流式消息、取消和审批只作用于原 thread。
5. 同一主机的多个 SSH 项目共用一个 Codex 服务入口，但不会串项目目录或会话。
6. 远端 Codex 失败时显示明确错误，且本机没有启动替代对话。
7. 本地项目的 Codex 行为保持不变。

## 十一、阶段输出与下一阶段入口

本阶段输出稳定的 thread 执行目标解析、SSH 远端 Codex 文本对话闭环和机器级远端运行时路由契约。计划 2 只能复用这些契约接入 OpenCode，不能改变 tunnel Map、项目目录随请求传递或本地/SSH 严格分流规则。
