# 第4阶段剩余工作阶段计划2：SSH 远端 OpenCode 对话闭环

## 一、文档定位

本文是第四阶段剩余工作的第 2 个实施计划。它在计划 1 已交付的执行目标分流和机器级远端运行时契约上，补齐 SSH 远端项目的 OpenCode 文本对话能力。

## 二、阶段目标

本阶段结束后，用户可以在 SSH 远端项目中创建或恢复 OpenCode 会话，通过项目绑定机器上的 OpenCode 完成文本对话、流式接收、取消、权限审批和问题回答。

## 三、业务范围

本阶段包含：

- 通过 `thread -> workspace -> sshConnectionId` 路由到远端 OpenCode。
- 通过 `hostId + opencode` 共用机器级 tunnel 和 OpenCode 服务。
- 每次 OpenCode 请求携带 `directory` 或 `X-OpenCode-Directory`。
- 支持新会话、恢复、发送、流式消息、取消、权限审批和问题回答。
- 模型、思考强度、Agent、权限及发送校验来自远端 OpenCode。
- 临时服务密码只存在于当前运行时内存和远端进程环境中。
- 与本地 OpenCode、远端 Codex 的状态和事件严格隔离。

本阶段不包含：

- Claude Code 正式对话。
- 本机附件上传。
- 三种 CLI 的统一账号、用量、MCP、Skills 展示。
- 手机入口和多机器综合收口。

## 四、业务结构

```text
SSH OpenCode thread
  -> workspace.sshConnectionId
  -> SshCliTunnelRegistry(hostId + opencode)
  -> 本机转发后的 HTTP/SSE 入口
  -> 请求携带当前 workspace.rootPath
  -> 远端 OpenCode session
```

同一远端机器的多个项目共用一个 OpenCode 服务和认证信息，但每个请求必须明确携带项目目录，每个 SSE 事件必须按 session/thread 归属。

## 五、主要工作

### 5.1 OpenCode 远端运行时接入

- 复用计划 1 的 ExecutionTarget 和远端运行时注册方式。
- 为 SSH OpenCode 建立独立客户端状态，不能复用本机 OpenCode 的 server/session Map。
- HTTP 请求和 SSE 订阅使用 tunnel 的本机端口及 Registry 保存的临时认证密钥。
- 服务密钥不得写入数据库、前端状态、普通日志或错误详情。

### 5.2 新建与恢复

- 新会话在请求中传入当前远端项目目录。
- 恢复已同步会话时校验 session 仍属于同一目录。
- 同一 session ID 只能绑定原 thread 和目标机器。
- 远端 session 不存在时明确提示，不能在本机按相同 ID 创建替代会话。

### 5.3 消息、事件和状态

- 消息请求使用远端模型、reasoning variant、Agent 和权限模式。
- SSE 订阅按机器服务共享，但事件必须按远端 session ID 路由到本地 thread。
- OpenCode permission 和 question 事件转换为现有审批块，并保留原远端请求路由。
- turn 完成、取消、错误时更新原 thread，不能依赖当前活动项目。

### 5.4 生命周期

- 每个正式 turn 对 `hostId + opencode + threadId` 建立持续占用。
- 多个项目并行使用同一远端 OpenCode 服务时，任一 turn 结束不能关闭其他 turn 使用的服务。
- 服务退出或 SSE 中断时，使该目标的 OpenCode 运行时失效并清理订阅；不得影响其他主机和 Codex。

## 六、计划修改范围

计划修改或新增：

- `src-tauri/src/commands/chat.rs`：在既有目标路由中启用 SSH OpenCode 分支。
- `src-tauri/src/commands/engines.rs`：增加远端 OpenCode 模型、Agent、权限及健康查询。
- `src-tauri/src/engines/`：新增 SSH OpenCode 独立协议适配或目标运行时实现。
- `src-tauri/src/ssh/cli_tunnel_registry.rs`：只补充远端 OpenCode 对话所需且现有契约缺失的入口信息。
- `src/stores/engineStore.ts`、`src/stores/chatStore.ts`、`src/components/chat/ModelPicker.tsx` 及 OpenCode Agent/权限相关组件。
- 对应 Rust、TypeScript 和组件测试。

明确不修改：

- 本机 `list_opencode_remote_sessions`、`attach_opencode_remote_session` 路线。
- 本地 OpenCode 服务启动和本地 session 语义。
- 计划 1 已固定的执行目标和 tunnel key。
- 第三阶段远端工作区能力。

## 七、异常与安全

界面至少区分：远端 OpenCode 未安装、服务启动失败、认证失败、HTTP 请求失败、SSE 中断、项目目录不匹配、模型或 Agent 不可用、权限/问题请求已失效。

认证密钥只能在运行时内存和远端进程环境中存在。认证失败后应使当前目标运行时失效并重新按需建立，不得把密钥写入持久化数据。

## 八、测试重点

- 远端 OpenCode 新会话和已同步会话恢复。
- 消息流、工具事件、权限审批、问题回答和取消。
- 两个远端项目共用一个 OpenCode 服务，directory、session 和事件不串线。
- 同一模型 ID 在本机与远端分别执行。
- 密钥不出现在数据库、通知载荷和日志中。
- 服务退出、SSE 中断、认证失败和 session 缺失。
- 本地 OpenCode 和计划 1 Codex 回归。

## 九、验收标准

1. SSH 项目中的 OpenCode 消息由绑定机器上的 OpenCode 执行。
2. 新建和恢复请求始终携带当前远端项目目录。
3. 模型、思考强度、Agent 和权限来自远端 OpenCode。
4. 流式事件、取消、权限审批和问题回答准确回到原 thread。
5. 同一主机多个项目共用服务但不会串 directory、session 或事件。
6. OpenCode 密钥未进入数据库、前端和普通日志。
7. 远端失败不会调用本机 OpenCode，本地项目行为保持不变。

## 十、阶段输出与下一阶段入口

本阶段输出 SSH 远端 OpenCode 文本对话闭环，并验证统一目标路由能够承载第二种 CLI。计划 3 在同一契约上接入 Claude Code，不得为 Claude 单独改变 tunnel Map 或项目归属规则。
