# SSH 远端功能实施计划 v2

## 一、文档定位

本文件是 SSH 远端功能的总实施计划，不代替各阶段设计文档。

本次不单独编写需求规格说明书。六个业务功能点各自形成一份“概要设计＋详细设计”文档，开发一个阶段前先以对应文档作为实现依据，完成后按文档中的验收标准验收。

总体技术约束和跨阶段架构见 [SSH 远端项目技术方案](ssh-remote-project-design.md)。

## 二、实施原则

1. 一个阶段只交付一块可识别、可操作、可验收的业务功能。
2. SSH 认证、执行目标解析、命令执行、数据传输、PTY 和端口转发等公共能力，放入首次需要它的业务阶段实现，后续阶段直接复用，不另设“基础设施阶段”。
3. 本地项目原有行为保持不变；远端项目失败时只返回远端错误，绝不改用本机文件、本机 Git、本机终端或本机 CLI 兜底。
4. SSH 连接、项目、对话、消息和定时任务使用稳定且不可变的 ID。删除 SSH 连接采用软删除，恢复必须复用原连接 ID，关联数据不改 ID。
5. 需要网络连接的远端 CLI 服务统一只监听远端回环地址，再通过 SSH 隧道转发；不为某个 CLI 建立绕开 SSH 通道的特殊连接方案。
6. 首版远端系统范围为 Linux；本地项目继续支持当前平台。
7. 每个阶段完成代码实现、自动化验证和文档验收后，再进入下一阶段。

## 三、六个实施阶段

### 第一阶段：SSH 连接管理

在设置界面完成远端电脑的添加和管理，包括扫描 `~/.ssh/config`、手动添加、检测、启用、禁用、软删除和按原 ID 恢复。

设计文档：[01-SSH 连接管理设计](ssh-remote-project/01-ssh-connection-management.md)

### 第二阶段：项目管理

改造主界面的“添加项目”，支持选择本地或远端，选择远端连接并浏览该机器目录，创建与该连接永久绑定的远端项目。

设计文档：[02-项目管理设计](ssh-remote-project/02-project-management.md)

### 第三阶段：项目工作区

让远端项目中的文件浏览与编辑、Git、工作树、终端和启动配置都在项目绑定的远端机器上执行。

设计文档：[03-项目工作区设计](ssh-remote-project/03-project-workspace.md)

### 第四阶段：对话管理

让远端项目的对话、模型、思考强度、权限、账号、健康状态和用量全部来自对应远端 CLI，并通过 SSH 隧道发送、接收和恢复会话。

设计文档：[04-对话管理设计](ssh-remote-project/04-conversation-management.md)

### 第五阶段：智能体运行工具

把智能体运行工具页面按“本地、远端 1、远端 2……”分组展示，并在当前项目所属机器上检测和启动智能体 CLI。

设计文档：[05-智能体运行工具设计](ssh-remote-project/05-agent-runtime-tools.md)

### 第六阶段：定时任务管理

让远端项目的定时任务按项目绑定关系调用远端 CLI；连接禁用或删除时可恢复暂停，恢复后保留原任务和执行记录。

设计文档：[06-定时任务管理设计](ssh-remote-project/06-scheduled-task-management.md)

## 四、阶段依赖关系

```text
第一阶段 SSH 连接管理
        │
        ▼
第二阶段 项目管理
        │
        ▼
第三阶段 项目工作区
        │
        ▼
第四阶段 对话管理
        │
        ▼
第五阶段 智能体工具
        │
        ▼
第六阶段 定时任务
```

- 第二阶段依赖第一阶段提供可用的 SSH 连接和远端目录查询能力。
- 第三阶段依赖第二阶段建立项目与 SSH 连接的稳定绑定。
- 第四阶段依赖项目绑定关系和 SSH 隧道能力。
- 第五阶段依赖远端终端能力与按机器隔离的 CLI 检测能力。
- 第六阶段在前五阶段完成后收口，复用第四阶段统一的消息发送入口，不重复实现远端 CLI 调用。

## 五、阶段交付要求

每个阶段必须同时交付：

- 对应业务界面和交互。
- 对应前端状态、后端命令及持久化结构。
- 本地与远端分支的自动化测试。
- 不可达、禁用、删除、权限失败等异常测试。
- 对应设计文档中列出的验收项。

阶段完成不等于立即发布。六个阶段全部完成后统一进行本地功能验收。

## 六、整体验收

1. 使用至少两台 Linux 远端电脑验证连接、项目、工作区、对话、智能体和定时任务彼此隔离。
2. 验证同一路径可以分别存在于不同远端机器，同一远端机器不能重复添加相同实际目录。
3. 验证切换项目后，文件、Git、终端、模型、权限、账号、用量和 CLI 会话随项目目标同步切换。
4. 验证删除 SSH 连接后项目被隐藏、定时任务暂停，恢复后所有原 ID 和数据保持不变。
5. 验证任何远端连接或 CLI 错误都不会触发本机后备执行。
6. 验证原有本地项目、本地对话、本地智能体和本地定时任务没有行为回归。
7. 按项目规定仅生成 `src-tauri/target/release/Panes.exe` 供本地验收，不生成安装包。
8. 用户完成实际测试并明确确认通过后，再依据后续指令处理推送和发布。
