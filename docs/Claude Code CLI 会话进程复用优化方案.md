# Claude Code CLI 会话生命周期优化方案

## 一、目标

同一个 Panes 会话的多轮消息复用同一个 Claude Code 会话句柄和 Claude Code 进程。

不同 Panes 会话分别使用自己的 Claude Code 会话句柄，互不共享。

一轮对话结束后，连续空闲 5 分钟才关闭对应的 Claude Code 会话。

## 二、职责划分

### 2.1 `ClaudeCodeCli`

`ClaudeCodeCli` 是 Claude Code 会话句柄生命周期管理类的唯一授权操作对象。

所有会话建立、后续消息发送、取消、审批和空闲关闭，都必须先进入 `ClaudeCodeCli`。

### 2.2 Panes 的 Claude Code 会话句柄生命周期管理类

新增 Claude Code 会话句柄生命周期管理类，负责：

- 启动并维护会话生命周期 MAP；
- 保存每个 Panes 会话对应的 Claude Code 会话句柄；
- 控制同一会话复用原会话句柄；
- 管理每个会话独立的 5 分钟空闲计时；
- 空闲超时后触发远端关闭；
- 记录远端组件返回的关闭结果。

MAP 的业务关系是：

```text
Panes 会话编号 → Claude Code 会话句柄
```

该管理类不对其他类开放。MAP 中 Claude Code 会话句柄的创建、取得、复用和关闭，只允许由 `ClaudeCodeCli` 操作。

### 2.3 Panes 的 Claude Code 远端组件

Panes 的 Claude Code 远端组件负责：

- 调用第三方组件建立 Claude Code 会话；
- 调用第三方组件的连续消息发送功能；
- 保存远端正在运行的 Claude Code 会话句柄；
- 根据调用方要求销毁指定会话句柄；
- 结束对应的 Claude Code 进程；
- 返回会话建立、消息发送和销毁结果。

远端组件不决定会话何时空闲关闭。5 分钟空闲关闭由 Panes 的 Claude Code 会话句柄生命周期管理类决定。

## 三、远端组件首先增加的功能

### 3.1 新增 HTTP 接口

在现有 `POST /command` 调用方式基础上，新增用于建立持续运行 Claude Code 会话的 HTTP 接口。

### 3.2 新增内部函数

在远端组件中新增一个与现有 `queryFn` 同类的内部函数。

该函数负责：

- 接收第一条消息；
- 建立 Claude Code 会话；
- 返回 Claude Code 会话句柄；
- 一轮对话结束后不关闭会话；
- 保留后续消息继续进入原会话的能力。

### 3.3 HTTP 接口调用内部函数

新增的 HTTP 接口调用该内部函数，并把 Claude Code 会话句柄返回给调用方。

### 3.4 新增后续消息发送功能

远端组件新增向已有 Claude Code 会话句柄发送后续消息的功能：根据 Panes 会话编号取得原会话句柄，调用第三方组件的 `streamInput()`，把第二轮及后续消息发送到原 Claude Code 会话，不重新建立会话，也不重新启动 Claude Code 进程。

### 3.5 新增当前轮次中断功能

远端组件新增只中断当前一轮对话的功能：停止当前正在生成的回答，同时保留 Claude Code 会话句柄和对应的 Claude Code 进程。

### 3.6 新增会话销毁功能

远端组件新增会话销毁功能。

该功能负责：

1. 根据 Panes 会话编号找到对应的 Claude Code 会话句柄；
2. 从远端组件的 MAP 中删除该会话句柄；
3. 结束该会话句柄对应的 Claude Code 进程；
4. 把销毁结果返回给调用方。

销毁结果必须明确表示本次销毁是否执行成功。

## 四、远端组件的会话句柄 MAP

远端组件启动一个会话句柄 MAP，用于保存当前仍在运行的 Claude Code 会话句柄。

业务关系是：

```text
Panes 会话编号 → Claude Code 会话句柄
```

每次建立新会话并取得会话句柄后，按照以下规则写入 MAP：

```text
MAP 中不存在该 Panes 会话编号
→ 写入会话句柄

MAP 中已经存在该 Panes 会话编号
→ 不重复写入
```

写入行为使用 `putIfAbsent` 语义，禁止同一个 Panes 会话保存两个 Claude Code 会话句柄。

## 五、远端组件的连续消息发送

同一 Panes 会话发送后续消息时：

1. 根据 Panes 会话编号取得原 Claude Code 会话句柄；
2. 调用第三方组件的 `streamInput()`；
3. 把新消息发送给原 Claude Code 会话；
4. 不重新调用现有 `queryFn` 建立新会话；
5. 不重新启动 Claude Code 进程。

一轮对话结束后，远端组件保留 MAP 中的会话句柄，等待后续消息或关闭要求。

## 六、Panes 侧的会话生命周期

### 6.1 首次发送消息

```text
ClaudeCodeCli
→ 操作会话句柄生命周期管理类
→ 当前 Panes 会话没有会话句柄
→ 调用远端组件新增的会话建立接口
→ 远端组件建立会话并返回会话句柄
→ 生命周期管理类保存会话句柄
```

### 6.2 后续发送消息

```text
ClaudeCodeCli
→ 操作会话句柄生命周期管理类
→ 取得当前 Panes 会话的原会话句柄
→ 通过远端组件发送后续消息
→ 远端组件调用第三方组件的 streamInput()
→ 消息进入原 Claude Code 会话
```

### 6.3 一轮对话结束

一轮对话结束后：

1. 保留当前会话句柄；
2. 为当前 Panes 会话启动独立的 5 分钟空闲计时；
3. 不关闭 Claude Code 会话；
4. 不删除会话句柄。

仍在生成回复、执行工具或等待审批时，不开始空闲计时。

### 6.4 5 分钟内再次发送消息

当前会话在 5 分钟内发起新一轮对话时：

1. 取消当前空闲计时；
2. 取得原 Claude Code 会话句柄；
3. 继续使用原会话句柄发送消息；
4. 新一轮结束后重新开始完整的 5 分钟计时。

其他 Panes 会话发送消息，不影响当前会话的空闲计时。

### 6.5 连续空闲 5 分钟

连续空闲 5 分钟后：

1. Claude Code 会话句柄生命周期管理类触发关闭；
2. 调用远端组件的会话销毁功能；
3. 远端组件删除会话句柄并结束对应的 Claude Code 进程；
4. 远端组件返回销毁结果；
5. 生命周期管理类记录销毁结果，仅用于后续 BUG 排查；
6. 生命周期管理类不根据该返回结果执行其他处理。

## 七、取消与审批

取消只中断当前会话的当前一轮，不销毁会话句柄。

当前一轮结束后，按照正常规则启动 5 分钟空闲计时。

审批必须绑定当前 Panes 会话和当前一轮。等待审批期间不计算空闲时间。

## 八、固定协作关系

```text
业务调用方
→ CliTool
→ ClaudeCodeCli
→ Claude Code 会话句柄生命周期管理类
→ Panes 的 Claude Code 远端组件
→ 第三方组件
```

其中：

- `ClaudeCodeCli` 是会话句柄生命周期管理类的唯一授权操作对象；
- Panes 侧生命周期管理类决定何时复用和何时关闭；
- 远端组件保存远端正在运行的会话句柄，并执行消息发送和实际销毁；
- 第三方组件负责运行 Claude Code 会话。

## 九、不在本次范围内

以下系统级关闭和清理不属于本次新增设计：

- 项目删除；
- SSH 连接断开；
- Panes 退出；
- 远端服务整体停止；
- Claude Code 进程异常退出。

本次只新增一轮对话结束后连续空闲 5 分钟的会话关闭行为。

## 十、验收标准

1. 第一条消息能够建立 Claude Code 会话并返回会话句柄。
2. 远端组件使用 `putIfAbsent` 语义保存新会话句柄。
3. 同一个 Panes 会话不能保存两个 Claude Code 会话句柄。
4. 同一会话的后续消息通过 `streamInput()`进入原 Claude Code 会话。
5. 同一会话连续发送三轮消息时，不重新启动 Claude Code 进程。
6. 不同 Panes 会话分别使用自己的 Claude Code 会话句柄。
7. 一轮结束后不足 5 分钟时，不关闭会话句柄。
8. 5 分钟内发送新消息时，继续复用原会话句柄。
9. 连续空闲 5 分钟后，生命周期管理类调用远端组件的销毁功能。
10. 远端组件从 MAP 删除句柄并结束对应的 Claude Code 进程。
11. 生命周期管理类只记录远端组件返回的销毁结果，不执行其他处理。
12. 不修改现有 SSH tunnel 生命周期管理结构。
