# 斜杠菜单功能改造

前端按下 `/` 后只有一个菜单。不同 CLI 工具只是菜单项的来源不同：有的返回 Skill，有的返回 Agent、Command、MCP；返回给前端的数据结构和展示方式必须相同。

## 唯一调用链

```text
前端按下 /
  → get_cli_extensions(cliId, workspaceId)
  → CliToolFactory.create(cliId)
  → 返回一个 CliTool 实现对象
  → cli.get_extensions(context)
  → 返回同一种扩展项数组
  → 同一个斜杠菜单展示
```

一次请求只会由工厂选择一个实现对象，不会同时调用三个 CLI。

## 四块结构

### 1. 唯一接口：`CliTool`

```rust
async fn get_extensions(
    &self,
    context: &CliExecutionContext,
) -> Result<Vec<ExtensionItemDto>>;
```

`CliExecutionContext` 必须携带当前项目的本地或 SSH 远端位置、项目根目录和 SSH 连接信息。实现类据此决定读取本地数据还是远端数据；远端读取失败时，不得回退读取本机数据。

### 2. 三个实现类

```text
CodexCli.get_extensions(context)
OpenCodeCli.get_extensions(context)
ClaudeCodeCli.get_extensions(context)
```

三个实现类的方法名、入参和返回类型完全相同。各自内部使用自己的方式读取数据：

- `CodexCli` 读取 Codex 实际支持的扩展；
- `OpenCodeCli` 读取 OpenCode 的 Skill、Agent、Command、MCP；
- `ClaudeCodeCli` 读取 Claude Code 实际支持的扩展。

CLI 内部的 SSH 调用、命令执行和结果解析都留在各自的实现类中，不新增 Provider、Registry、Runtime Catalog 等中间对象。

### 3. 唯一工厂：`CliToolFactory`

```rust
let cli: Arc<dyn CliTool> =
    CliToolFactory::new(state.clone()).create(&cli_id)?;
```

工厂只根据 `cliId` 返回 `CodexCli`、`OpenCodeCli` 或 `ClaudeCodeCli` 之一，不读取扩展数据。

### 4. 唯一业务调用：`get_cli_extensions`

```rust
let context = /* 按 workspaceId 构造 CliExecutionContext */;
let cli = CliToolFactory::new(state.clone()).create(&cli_id)?;
let items = cli.get_extensions(&context).await?;
```

业务调用只负责构造上下文、从工厂取得一个对象、调用一次 `get_extensions`。业务调用中不得按 `codex`、`opencode`、`claude` 分支取数。

## 统一返回数据和前端展示

三个实现类返回 `ExtensionItemDto[]`。每个菜单项至少包含：

```text
id          菜单项标识
kind        skill、agent、command、mcp 等，用于选择小图标
name        菜单 label
description 菜单说明
insert_text 选择后插入输入框的文本
```

前端只调用一次：

```ts
ipc.getCliExtensions(selectedEngineId, activeWorkspaceId)
```

前端只维护一个菜单组件：根据 `kind` 选择图标，显示 `name` 和 `description`，按 `insert_text` 完成输入。不再按 CLI 工具分别调用 `list_codex_skills`、`get_extension_catalog`、`get_opencode_runtime_catalog`，也不保留三套菜单适配器或三套扩展状态。
