# CLI 工具层与 SSH 生命周期层边界设计

## 一、文档定位

本文是以下两份架构设计文档的边界补充：

- [多 CLI 工具统一接口架构设计](多%20CLI%20工具统一接口架构设计.md)
- [SshCliTunnelRegistry 生命周期管理](ssh-remote-project/SshCliTunnelRegistry%20声明周期管理.md)

本文只说明两套架构之间的职责边界、调用方向、代码归属和禁止修改范围。

本次 CLI 工具结构重构只能整理 CLI 业务代码，不能改变现有 MAP 和远端 CLI 服务生命周期管理架构。

## 二、边界结论

两层的边界固定为：

> CLI 工具层负责“当前 CLI 要做什么，以及怎样使用该 CLI 的协议完成业务”；SSH 生命周期层负责“远端 CLI 服务什么时候创建、复用和关闭”。

CLI 工具层是业务和协议的使用方。

SSH 生命周期层是 tunnel、远端服务和占用关系的资源管理方。

两层只能单向调用：

```text
CLI 工具业务实现
    ↓ 申请使用
现有 SSH 生命周期管理 API
    ↓
SshCliTunnelRegistry
```

`SshCliTunnelRegistry` 不反向依赖任何 CLI 业务接口。

## 三、CLI 工具层职责

CLI 工具层按照 Codex、OpenCode、Claude Code 分目录放置现有业务实现。

CLI 工具层负责：

- 当前选择的是哪个 CLI；
- 当前 CLI 支持哪些现有业务能力；
- 如何构造当前 CLI 的请求；
- 如何解析当前 CLI 的响应；
- 如何发送、恢复和取消当前 CLI 会话；
- 如何处理当前 CLI 的审批；
- 如何查询当前 CLI 的模型和扩展；
- 如何把附件转换成当前 CLI 已有协议需要的格式；
- 如何把当前 CLI 的原始结果转换成现有业务返回值。

CLI 工具层通过统一接口组织现有代码，但不能改变现有业务实现。

例如，获取可用扩展时：

```text
调用方
    ↓
CliExtensionProvider 统一接口
    ↓
当前 CLI 的具体实现
    ↓
现有本机或 SSH 调用链
```

Codex、OpenCode 和 Claude Code 分别实现同一个接口。调用方只持有接口类型，不直接判断具体 CLI 的协议细节。

## 四、SSH 生命周期层职责

SSH 生命周期层继续由现有 `SshCliTunnelRegistry` 和相关生命周期调用链负责。

生命周期层负责：

- 维护全局 `hostId -> cliId -> tunnel` MAP；
- 根据 `hostId + cliId` 取得既有 tunnel；
- 创建或复用远端 CLI 服务入口；
- 维护临时占用数量；
- 维护持续会话占用及其引用计数；
- 协调远端 CLI 服务的启动、等待和关闭；
- 判断远端 CLI 服务何时允许关闭；
- 维护现有服务状态；
- 维护现有运行时实例有效性；
- 执行连接变化和程序退出时的既有清理流程；
- 向业务层提供可用的本机连接入口或运行时使用权。

生命周期层不负责：

- 解析模型目录；
- 解析扩展目录；
- 构造聊天消息；
- 解析 CLI 事件；
- 管理用户选择的模型；
- 管理 `/` 菜单；
- 判断项目业务归属；
- 更新会话列表；
- 保存业务数据库记录。

## 五、所有权矩阵

| 内容 | CLI 工具层 | SSH 生命周期层 |
| --- | --- | --- |
| 当前 CLI 的业务能力 | 负责 | 不负责 |
| CLI 请求和响应协议 | 负责 | 不负责 |
| 模型、扩展、会话和审批语义 | 负责 | 不负责 |
| 附件的 CLI 协议格式 | 负责 | 不负责 |
| `/` 菜单业务数据 | 负责 | 不负责 |
| `hostId + cliId` 服务管理单位 | 不负责 | 负责 |
| 全局 tunnel MAP | 不负责 | 负责 |
| tunnel 创建和复用 | 不负责 | 负责 |
| 远端 CLI 服务启动和关闭 | 不负责 | 负责 |
| 临时占用 | 申请和释放 | 记录和管理 |
| 持续占用 | 申请和释放 | 记录和管理 |
| 引用计数 | 不负责 | 负责 |
| 服务状态和关闭判定 | 不负责 | 负责 |
| 生命周期清理 | 不负责 | 负责 |

## 六、两层调用契约

### 6.1 CLI 工具层只能申请和释放使用权

CLI 工具层只允许通过现有生命周期 API 完成以下动作：

```text
申请临时占用
释放临时占用
申请持续占用
释放持续占用
取得生命周期层提供的运行时或连接入口
```

CLI 工具实现取得使用权后，才执行自己的协议调用。

CLI 工具实现完成业务后，必须沿用现有流程释放使用权。

### 6.2 CLI 工具层不能管理远端服务

CLI 工具层不得：

- 直接读写全局 tunnel MAP；
- 自己保存脱离生命周期管理的 tunnel；
- 自己维护临时占用数量；
- 自己维护持续会话引用计数；
- 自己判断远端 CLI 服务是否应关闭；
- 因自身请求结束而直接关闭远端服务；
- 绕过现有申请和释放接口；
- 创建第二套远端服务生命周期管理器。

### 6.3 生命周期层不理解 CLI 业务

`SshCliTunnelRegistry` 只接收管理资源所需的稳定标识和占用凭证。

它不读取或判断：

- Skill、Plugin、Agent、Command、MCP；
- 模型能力；
- 消息内容；
- 审批类型；
- 会话标题；
- `/` 菜单项目；
- 当前页面状态。

## 七、典型调用流程

### 7.1 查询 SSH 扩展目录

```text
前端业务调用
    ↓
统一扩展接口
    ↓
当前 CLI 的扩展实现
    ↓
通过现有生命周期 API 申请临时占用
    ↓
SshCliTunnelRegistry 创建或复用现有远端服务
    ↓
当前 CLI 的扩展实现执行现有查询协议
    ↓
当前 CLI 的扩展实现解析现有响应
    ↓
释放临时占用
    ↓
SshCliTunnelRegistry 按现有规则判断服务是否允许关闭
```

其中：

- 当前 CLI 实现决定查询内容和解析方法；
- 生命周期层决定远端服务如何取得和何时关闭。

### 7.2 发送 SSH 对话消息

```text
前端发送消息
    ↓
统一对话接口
    ↓
当前 CLI 的对话实现
    ↓
通过现有生命周期 API 申请或使用持续占用
    ↓
SshCliTunnelRegistry 提供现有服务入口
    ↓
当前 CLI 的对话实现发送并解析消息
    ↓
持续对话结束时释放占用
    ↓
SshCliTunnelRegistry 执行现有关闭判定
```

其中：

- 当前 CLI 实现负责消息协议和事件映射；
- 生命周期层不读取消息内容，也不判断对话业务结果。

## 八、接口解析器与生命周期 Registry 的区别

CLI 工具统一接口可以使用一个无资源所有权的解析器，根据 `cliId` 返回对应业务实现：

```rust
let cli_tool: &dyn CliTool = cli_tool_resolver.resolve(cli_id)?;
```

该解析器只负责：

```text
cliId -> CLI 业务实现
```

它不得保存或管理：

- SSH tunnel；
- 远端服务进程；
- 服务端口；
- 临时占用；
- 持续占用；
- 引用计数；
- 服务状态。

现有 `SshCliTunnelRegistry` 负责：

```text
hostId + cliId -> tunnel 和远端服务生命周期
```

两者名称相似，但职责完全不同，不能合并。

为避免误解，CLI 工具层推荐使用 `CliToolResolver` 或 `CliToolFactory` 命名，不使用另一个带有资源管理含义的 Registry 名称。

## 九、代码归属边界

### 9.1 可以归入 CLI 目录的代码

满足以下条件的现有代码可以按 CLI 归类：

- 只服务于 Codex、OpenCode 或 Claude Code 中的一个；
- 负责该 CLI 的请求和响应协议；
- 负责该 CLI 的模型、扩展、会话、消息、审批或附件业务；
- 不拥有 tunnel MAP；
- 不维护远端服务占用关系；
- 不负责远端服务关闭判定。

### 9.2 不得移动或修改的生命周期代码

只要现有代码承担以下任一职责，就属于受保护的生命周期层：

- 持有或操作全局 tunnel MAP；
- 申请或释放临时占用；
- 申请或释放持续占用；
- 维护引用计数；
- 维护服务状态；
- 协调远端服务启动、等待和关闭；
- 判断服务何时允许关闭；
- 在 Drop、退出或连接变化时执行生命周期清理。

这些代码不得因为包含 `codex`、`opencode` 或 `claude` 名称就迁入 CLI 目录。

以下现有文件是明确保护对象：

```text
src-tauri/src/ssh/cli_tunnel_registry.rs
```

与该文件配套的现有生命周期调用顺序、MAP 结构、管理单位和关闭判定同样不得改变。

### 9.3 桥接代码的判断方法

某个文件同时包含 CLI 名称和生命周期调用时，按照“资源所有权”判断归属：

- 如果代码决定调用什么 CLI 协议，属于 CLI 工具层；
- 如果代码决定远端服务如何申请、复用、释放或关闭，属于生命周期层；
- 如果两类职责目前混在同一文件中，本次重构不得重新设计生命周期逻辑；
- CLI 工具接口只能包裹或调用现有生命周期入口，不能复制其中代码。

## 十、禁止事项

本次 CLI 工具结构重构禁止：

1. 修改全局 tunnel MAP 的层级和 key。
2. 把 `workspaceId`、项目目录或 `threadId` 加入 tunnel MAP 的 key。
3. 修改 `hostId + cliId` 的生命周期管理单位。
4. 修改临时占用和持续占用的现有含义。
5. 修改远端 CLI 服务关闭判定。
6. 移动、重写或替换 `SshCliTunnelRegistry`。
7. 新建第二套 tunnel MAP。
8. 新建第二套远端服务生命周期管理器。
9. 让 CLI 工具实现直接启动或关闭远端服务。
10. 让生命周期层依赖 CLI 业务接口。
11. 借结构重构修改现有业务行为。
12. 借结构重构修复 BUG、优化性能或新增功能。

## 十一、重构后的稳定关系

重构完成后，稳定关系必须保持为：

```text
业务调用方
    ↓
统一 CLI 接口
    ↓
当前 CLI 目录中的现有业务实现
    ↓
现有生命周期申请和释放入口
    ↓
SshCliTunnelRegistry
    ↓
现有 tunnel 和远端 CLI 服务
```

CLI 工具代码结构可以整理，生命周期资源所有权不能变化。

统一 CLI 接口可以替换调用方对具体 CLI 业务函数的直接依赖，但不能替换、包办或绕过 `SshCliTunnelRegistry`。

## 十二、结构重构检查

重构每个现有文件前，必须依次确认：

1. 该文件是否持有或操作生命周期 MAP。
2. 该文件是否维护临时占用或持续占用。
3. 该文件是否参与远端服务启动和关闭判定。
4. 该文件是否只实现某个 CLI 的业务或协议。
5. 移动该文件是否会改变现有调用顺序。
6. 接入统一接口后，是否仍调用原生命周期入口。
7. 重构前后，远端服务的申请、复用、释放和关闭行为是否完全一致。

任何一项涉及生命周期资源所有权时，该部分都不得移动或修改。
