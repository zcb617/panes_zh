## OpenCode 远端 skills 数据入口确认（panes_zh-ssh-remote-project worktree）

排查"远端 OpenCode 按 / 没有 Skill 菜单"问题，确认了 A 步（数据层）的取数入口：

- OpenCode **通过 HTTP API 暴露 skills**：`GET /skill`（Go SDK `opencode-go-sdk-lite` 用 `/skill`；官方 V2 文档用 `/api/skill`）。返回 `Skill.Info[]`：`id, name, description, slash, autoinvoke, location, content`。
- 远端 OpenCode 运行时走 `OpenCodeEngine::new_remote_http`，直接打远端机器的 OpenCode HTTP 服务（经 SSH 隧道）。`runtime_catalog`（`engines/opencode.rs:1300`）目前只查 `/agent /command /mcp`，缺 `/skill`。
- 新增请求会自动带 `X-OpenCode-Directory` 头（远端 server `include_directory_header=true`），与 `/agent` 一致，无需手动加 query。
- 待修：① `models.rs:581` 的 `OpenCodeRuntimeCatalogDto` 加 `skills` 字段；② `engines/opencode.rs::runtime_catalog` 加 `GET /skill` + `map_runtime_skills`；③ `cli_tools/opencode.rs` SSH 分支组装 `ExtensionItemDto(kind:"skill")` 并加入 `kind_fetched_at`。
- 待验证歧义：路径是 `/skill` 还是 `/api/skill`（Panes 现有 agent/command/mcp 无 `/api` 前缀，倾向 `/skill`）；以及 `/skill` 是否同样认 `X-OpenCode-Directory` 头。

本地 OpenCode 的 skills 走的是另一条路（`opencode debug skill` CLI → `extensions/opencode.rs::parse_skills`），与远端无关。
